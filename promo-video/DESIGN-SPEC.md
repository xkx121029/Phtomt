# Happy Agent 宣传片 · 设计 spec

> 模式：自主自由创作（用户 2026-11-06 选定） · 画幅 1920×1080 · 30fps
> 流水线阶段 0–3 由 Agent 自主完成并记录，供阶段 7 独立终检对照。

## 1. 产品简报

| 项 | 内容 |
|---|---|
| 产品 | Happy Phone Agent（应用名 Happy Agent），Android 端 AI 智能体 |
| 一句话 | 你说一句人话，手机自己把事做完 |
| 机制 | 无障碍 / 内嵌 Shizuku / Termux 三条通道装在独立 Provider APK，主应用经 AIDL 远程驱动；AI 只输出意图（44 个），端侧转译层算坐标、选通道 |
| 差异化 | AI 不写命令、不盲点；每步有页面证据与页面指纹验证；敏感页只读 + 脱敏 + 不可逆动作二次确认 |
| 视觉 | Material 3 Expressive + Compose，深色，玄青/赭石/黛蓝/绛紫四套色板 |
| 用途 | 官网 / README 顶图视频 / 发布会片段 / 社交平台横版 |
| 受众 | 关注「AI 手机」的开发者与重度手机用户；懂一点技术，不吃虚的 |

### 需求到执行决策

| 决策项 | 取值 | 依据 |
|---|---|---|
| 叙事主线 | 一条真实任务全程（「帮我把手机字体调大一点」），不用功能清单流水账 | 产品价值只在「真的做完了」这一件事上；清单流说服力弱 |
| 时长 | 约 50s | 超过 60s 的信息留存断崖；短于 40s 装不下一条完整任务 + 品牌 |
| 语言 | 简体中文 | 目标用户与产品文案均为中文 |
| 数据口径 | 全部虚构：文案里的任务、步骤、statistics 均为演示值，不含任何真实账号/订单/个人信息 | 无公开演示数据授权，一律虚构 |
| 素材来源 | 应用内 UI 全部来自 `promo/app.html`（1:1 复刻 Compose 的浏览器可驱动版本）的 3x 截图；被操作的系统页来自 Android 模拟器真截图；不使用真机图（真机会话含个人笔记，已排除） | Q1：复刻既有页面必须真实截图 |
| 音频 | BGM 用库内 tech-house 备选（强鼓点电子），SFX 从 Freesound 按动作选取；交付带 BGM / 无 BGM 两版 | S1 |

## 2. 视觉方向

三个候选方向，选定 **B. 暗场仪器（Instrument in the dark）**。

| 方向 | 描述 | 判决 |
|---|---|---|
| A. 明亮产品页 | 浅色背景 + 大留白 + 卡片 | 否决：产品是深色玄青，蒙皮后要靠改产品色，等于另造皮肤 |
| **B. 暗场仪器** | 近黑舞台，一台发光的设备是唯一光源，UI 自发光，标注像仪器读数 | **采用**：直接长在产品色板上；设备发光本身是「AI 在替你操作」的物理隐喻 |
| C. 霓虹故障 | glitch、扫描线故障、高饱和 | 否决：故障感与「可信赖、有验证」的产品调性相反 |

### 字体

- 正文/标题：`Noto Sans SC`（已装 VF），字重 300/400/500/700
- 强调衬线（仅字标副句）：`Noto Serif SC`
- 机器读数/参数：`Cascadia Mono`
- 字幕有效字高 ≥56px，辅助 ≥32px（Q11）

### 动效性格 tokens

品牌两轴：能量**中低**（工具型、可信赖，不炫技）× 调性**严肃偏冷**（工程感）。
最近预设：专业信赖，但玄青的冷调与「AI 自己动」的活性需要一点弹性 → 微调：

| 参数 | 取值 |
|---|---|
| 主入场时长 | 22–26f @30fps |
| 入场 easing | `cubic-bezier(.16,1,.3,1)`（out-expo 感） |
| 落地过冲 | 1.0–1.04（仅带落地隐喻的元素允许 y1>1，如设备就位、卡片嵌入） |
| 相机 easing | `cubic-bezier(.33,0,.15,1)`，恒定缓速，无手持抖动（Q3） |
| hold | 字标 ≥35f；批量动效收尾 ≥15f |
| 三个词自检 | 「冷静、精确、有重量」 |

### 与流程骨架的有意偏离

`promo-energy-arc` 的段位①是「品牌字标开头」。本片把字标挪到结尾，开场用
**用户的一句话**当钩子——产品价值在体验而非名号，开场立名号等于浪费最贵的
第一印象。品牌记忆点由结尾 hold ≥1s 承担（R1 未被违反）。

### 转场（成片实际）

全片 8 个接缝里 7 个是**直切**（不叠化、不闪白）：本片靠每个镜头首帧的能量差与拍点落位区分镜头，加转场反而泄力。

| 接缝 | 实际做法 |
|---|---|
| S1→S2 | 直切（胶囊淡出前一刻切；暗场到暗场，切点无跳感） |
| S2→S3 | 直切（同一主体换屏） |
| S3→S4 | 直切（应用内 → 系统页，语义跳变） |
| S4→S5 | 直切（扫描线出画后立刻 drop，b52 的 impact 承担接力） |
| S5→S6 | bottom-push（完成屏自下方推入，唯一有方向的接缝） |
| S6→S7 | 直切（四宫格本身就是切点） |
| S7→S8 | 收拢：四块画面 → 图标（截图在收拢前 20% 内退净，不留被切断的字） |

## 6. 声音落地（阶段 6）

### 6.1 BGM
`cat-walk.mp3` 自 64.636s 起裁 49.195s，48kHz 立体声 → 源文件存 `audio-src/bgm.wav`，进片用 `public/audio/bgm.mp3`（192k，体积从 9.1MB 降到 1.2MB，避免拖慢渲染）。
节拍网格：BPM 130.014 / 拍长 0.46149s / 最小二乘残差 ±10.5ms，0 秒 = 第 0 拍
（`analysis/beat_data.json`）。混音音量 0.42（素材实测 mean −13.2dB / max 0.0dB，
留出 SFX 头空间），首 14f 淡入、末 34f 淡出。

### 6.3 钉帧表（表达式在 `src/film/audio.ts`，此处只记语义）
输出偏移 `OUTPUT_AUDIO_OFFSET_F = 0.56`（AAC priming 实测 1.28f，取整后取 0.56 使残差最小），
`Sequence.from = 目标峰值帧 − 音源峰值滞后 − 1.28`。

- S1：`+beatF(2.2)` 打字 0.5，窗口 28f。
- S2：`+beatF(6)`（升起落定）whoosh 0.55。
- S3：`+beatF(1.8/3.6/5.4)` 三行揭盖 click 0.30/0.26/0.22；`+beatF(9)` 批准 0.34。
- S4：四个取景框锁定 click 0.26/0.23/0.20/0.17（音量阶梯递减，防机枪感）。
- S5：`+0` drop impact 0.62；`+beatF(1.6/3.4/5.2)` 三步落定 click 0.28/0.24/0.20。
- S6：`+beatF(2.6/5.2)` 计数 click 0.22/0.24；`+beatF(8)` 3/3 砸落 impact 0.78（全片最重）。
- S7：`+0/4/8/12` 四格亮起 click 0.30→0.21；`+beatF(4)` 换色板 0.26。
- S8：`+beatF(4)` riser 0.50（3.0s，峰值落在 b88）与 impact 0.72 同拍；`+beatF(12)` sparkle 0.50（字标落定余韵）。

### 6.4 渲后回测（2026-11-07，管线：Remotion 4.0.484 + h264/aac 48kHz mp4 + Edge 内核）

- 探针：`fs-755054` 的两个 impact 钉点（b72 帧 997、b88 帧 1218）。
  `tools/measure_offset.py` 对渲出音轨做归一化互相关（互相关给的是文件头落点，
  再叠加音源自身 sample peak 5.09f）。
- 结果：996.37f / 1217.38f → 残差 **+0.62f / +0.63f**（提前 0.02s），两点一致性 0.01f。
  click 探针（帧 767 / 1107）残差 +0.28f。
- 残差来源：`Sequence.from` 只能取整，0.28–0.63f 已是本管线的下限；
  输出偏移实测 ≈ 1.28f（与 AAC priming 指纹一致）；代码里取 `OUTPUT_AUDIO_OFFSET_F = 0.56`，是因为 `from` 只能取整，0.56 让两个探针的残差落在 +0.62f（若取 1.28 则为 +1.3f）。
- 电平：带 BGM 版 max −0.6dBFS / mean −20.0dBFS；无 BGM 版 max −1.1dBFS / mean −27.4dBFS，均未削波。

## 7. 实现偏离记录（对 §4 分镜表）

- **S1 开场**：计划里是品牌字标开场，实拍改为「用户那句话」当钩子，字标整段挪到 S8
  （R1 的 1s hold 由 S8 满足：b96→b104 = 8 拍 3.7s）。
- **S3 步数**：4 步 → 3 步。`promo/app.html` 的 `.plan-panel` 第 4 行会被 CTA 按钮切掉，
  且 3 步更利于「每步有证据」这句话的可读性。
- **S5 落定语言**：点击涟漪 → 整行卡片描边亮起。涟漪画在 3D 内容层里与真实状态位对不齐，
  且真实截图右侧 gutter 自带小圆点，叠加后读作脏点。
- **S6/S7 内容层不推近**（`contentZoom = 1.0`）：任何 >1 的推近都会切掉状态栏/标题，
  与「这是真机截图」的诚实性冲突；锐度已由 4x 截图 × zoom 布局放大保证（Q2），不靠裁切。
- **S7 四宫格**：设备四宫格 → 无边框屏幕窗口四宫格 + 双向渐隐。960×540 格里放设备必然横向切字，
  加机身反而强调「被切断」；改成满宽窗口 + 上下渐隐后，切边读作取景而非穿帮。
- **S8 分镜缩水**：计划里的「9 元素 12f 飞入 ±360–500px 围住字标」（发布会合影式收场）改为
  「四块全屏画面收拢成 2×2 应用图标 → 字标落定 → 光爆 + 金尘」。理由：本片全部素材都是
  竖屏 412×892 的整屏截图，把 9 个「元素」从整屏里裁出来围成合影会得到 9 块互不相干的碎片；
  收拢成一个图标反而与真实 App 图标同构。**代价**：结尾没有「合影」手法（Q8 的手法多样性少一种），
  且 b88 的冲击只靠光爆与画面泵，不靠元素合围。
- **S7 第四格**：标签由「四套色板」改为「主题换肤」。素材只有 `home.png` / `home-ochre.png`
  两个状态，说「四套」观众数不出来（终检 F3 判为表达失效）；改成「换肤」后与画面对得上。
- **S1 副提示**「按住说话 · 或者直接打字」保留但压暗（打字完成后随胶囊一起淡出）。它是输入框
  的真实附属说明，不承担叙事；不放大是因为它一旦可读就会跟主台词抢注意力。

## 8. 多版本交付（竖版 9:16 + 15s 短版）

在阶段 7 之后追加需求「多做几个」，指定两版：**竖版 9:16 长版 48s**、**横版 15s 短版**。

原则：**不新开一条时间线**。两版共用 `beat.ts` 的节拍网格与镜头表，共用 `audio.ts` 的 SFX 钉帧表
（短版是唯一例外，见 8.4）；变的只有「画面怎么排」和「取多少段」。

### 8.1 竖版是重新构图，不是裁切

把 1920×1080 居中裁成 1080×1920 会毁掉每一镜：横版的语法是「设备偏右、字幕左下」的横向对位，
裁掉左右两边后设备只剩半个、字幕全丢。所以竖版按 9:16 重新定了分区（`vertical/vertical-beat.ts`）：

| 分区 | 位置（1080×1920） | 内容 |
| --- | --- | --- |
| 安全区 | 左右各 76 | 内容宽 928 |
| 眉标 | y 142–190 | mono 30 / 字距 0.2em |
| 主标题 | y 206 起 | sans 76（横版 56），可 2 行，居中 |
| 副行 | 标题下 22 | sans 38 |
| 设备 | y 560 起 | 屏宽 600–620，屏高 1299–1342，下缘出血 |

竖版最大的红利是**设备可以放大近一倍**：9:16 画幅刚好等于手机屏比例，屏宽 600 时屏高 1299，
顶端压在 560 就几乎铺满画幅。横版为了留字幕只能给 392–474。

### 8.2 三处必须重排（不能照搬横版数值）

- **S4 标注**：横版标注在设备右侧、用引出线连到框，`labelX = 1262`；竖版设备居中后两侧只剩约 200px，
  放不下 44px 的 mono 标签。改为「顶部读数清单」：屏内只留四角括线，01–04 编号与标签上提到 y 224 起的
  四行清单，靠「扫描线越过框底那一帧」同步出现来建立对应（不靠引出线）。清单行首加一枚同形括角，
  与屏内取景框同一种语法。
- **S3 计划卡**：横版是「设备退后当背景 + 面板抽成前景卡」两层；竖版只有一层——卡片铺满安全区宽 928
  （`S = 928/370`，卡高 592），因为 1080 宽里再塞一台设备，两层都会读不清。倾角也从 `rotY −16→−7`
  收到 `−13→−5`：卡越宽，同样的角度越容易出画。
- **S8 收尾**：横版是「标记在左、字标在右」的横向排布；竖版改纵向居中——图元（2×2 / 96px 方块）在上，
  字标（104px）在下，再下面是横线与标语。三段的纵向间距按 `258 / 268` 排，横线刻意与字标降部留出 4px。

顺带修掉两处「横版数值搬过来会穿帮」的细节：
- 屏内编号牌方案被否——真机界面从 `x=11` 铺到 `x=401`，412 宽的屏没有一处空隙能安全承载编号牌，
  任何位置都会压住真实文字（首版实测：`01` 压住亮度行的残字、`02` 压住「已显示屏」）。
- `Device` 的 `perspectiveOrigin` 原写死 `960px 540px`（横版中心），竖版必须换成 `540px 960px`，
  否则所有 3D 镜头的光轴都偏。改为从 `useVideoConfig()` 取画幅中心，两个画幅自动对。

### 8.3 复用与参数化清单

竖版 8 个镜头里，2 个直接复用横版组件、6 个重写（只重排布局，视觉语法与横版同一套 tokens）。

| 镜头 | 竖版实现 | 复用方式 |
| --- | --- | --- |
| V1 一句话 | `shots/S1Sentence` | 参数化 `pillTop / pillW`（958 / 900） |
| V2 升起 | `vertical/V2Rise` | 复用 `Device`，屏宽 392→600，旋转幅度按比例减半 |
| V3 规划 | `vertical/V3Plan` | 复用 `agent-plan-panel.png` + 逐行揭盖语法，几何全部按 `S = 928/370` 重算 |
| V4 框选 | `vertical/V4Scan` | 复用 `Device` + 扫描线 + 四角括线，标注改清单 |
| V5 执行 | `vertical/V5Exec` | 复用 `Device`，`contentZoom` 1.06（横版 1.0），工具行更大 |
| V6 完成 | `vertical/V6Done` | 读数主体化（数字 248px），设备 `sw` 428→524 |
| V7 四宫格 | `shots/S7Wall` | 参数化 `qw / qh`（540 / 960）——格子正好是 9:16 |
| V8 收尾 | `vertical/V8Outro` | 复用四块收拢语法，起点从 960×540 四格换成 540×960 四格 |

否则 9:16 里的字幕区会落在压暗带之外。

### 8.4 15s 短版：32 拍，只借不重建

短版只借原曲的一段：从原 BGM 第 59 拍（27.228s）起裁 15.2s 作 `public/audio/bgm-short.mp3`，
使短版第 0 拍 = drop 前的 8 拍铺垫，drop 正好落在短版第 13 拍。

时间表在 `src/film/audio-short.ts`：

| 段 | 拍 | 帧 | 镜头 | 与长版的关系 |
| --- | --- | --- | --- | --- |
| T1 钩子 | 0–5 | 0–69 | `S1Sentence` `typeStartBeat=0.6 / charFrames=1.6` | 打字压到 1.6f/字 |
| T2 扫控件 | 5–13 | 69–180 | `S4Scan` | 原样复用（内部时序本就是 8 拍） |
| T3 执行 | 13–20 | 180–277 | `S5Exec` | 原样复用，drop 落在 T3 第一拍 |
| T4 品牌 | 20–32 | 277–443 | `S8Outro` `slamBeat=4 / markBeat=9` | 落标从 b12 提前到 b9 |

SFX 13 条，钉帧仍走 `sfxFrom()`（同一套 `PEAK_F` 与 `OUTPUT_AUDIO_OFFSET_F`），只是目标帧换成短版时间轴。

### 8.5 实测（2026-11-07，管线同上）

| 交付 | 分辨率 | 时长 | 帧数 | 体积 | max / mean（带 BGM） | max / mean（无 BGM） |
| --- | --- | --- | --- | --- | --- | --- |
| `out/promo.mp4` | 1920×1080 | 48.064s | 1440 | 11.6 MB | −0.6 / −20.0 dBFS | −1.1 / −27.1 dBFS |
| `out/promo-vertical.mp4` | 1080×1920 | 48.064s | 1440 | 14.8 MB | −0.6 / −20.0 dBFS | −1.1 / −27.1 dBFS |
| `out/promo-short.mp4` | 1920×1080 | 14.827s | 443 | 3.9 MB | −0.5 / −17.2 dBFS | −0.6 / −22.9 dBFS |

三版均为 h264 + aac 48kHz 立体声，30fps，未削波。

**音画回测**：
- 竖版（与长版同一条音轨）：997f / 1218f 探针 → 996.37f / 1217.38f，残差 **+0.63f / +0.62f**，一致性 0.01f。
- 短版：180f（T3 drop）探针 → 残差 **+0.62f**，与长版同值，说明 `sfxFrom()` 的算式在短版时间轴上同样成立。

**回测方法论修正**：短版 295f（T4 落标）探针曾测出 −19.64f 的假残差。原因是短版 T4 仍处在原曲 drop 段，
BGM 的 kick 与 impact 同为低频冲击，互相关被音乐抢锁。改用**整轨法**复核：把 `bgm-short.mp3` 第 2–7s
当探针与渲出音轨做全片对齐，得 lag **+1.25f**（相关 0.678，与长版实测的 1.28f 管线常数一致）——
说明全轨只晚 1.25f，SFX 侧的 0.62f 残差是「预补偿 0.56f 之后的余量」，而不是错位。
结论：**探针落在有鼓点的段落里时不可信，应以整轨 BGM 对齐为准。**

### 8.6 已知取舍

- **竖版 V1 上下留白很大**（胶囊只占中间一条）。有意为之：这是钩子镜头，1–4 秒里除了那句话不该有别的东西；
  9:16 竖屏观看时视线本来就集中在中央。
- **竖版 V2/V4/V5 的设备下缘出血**（33–43px）。出血让「这台手机还在往下延伸」，比硬留一圈黑边更像真机演示；
  代价是机身底部的圆角看不到。
- **竖版 V7 的格子是 540×960**，设备按 504 宽铺进去后纵向被裁掉约 15%，靠四边渐隐读作取景窗口
  （与横版同一个手法，只是裁切方向不同）。
- **短版 T1 直接硬切**：`S1Sentence` 的收尾（光标塌成点 + 胶囊淡出）需要约 40f，69f 的 T1 里放不完，
  所以打字结束后直接切 T2。这是 7 直切语法下的合理选择，但也意味着短版没有「一句话沉降成屏幕光」的过渡。
