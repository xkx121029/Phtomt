EVERY DAY

一天里，你要点开多少个 App

微信 日历 外卖 银行 相册 地图
THE SAME PATH

每个 App 里，都要走一遍同样的路

打开 找入口 关弹窗 跳过广告 复制粘贴

每一步
都要你亲手做

可手机本身
一直有能力自己做

它只是从来没人告诉它，你要什么

INSTEAD

你其实只想说一句话

你说 打开微信，给张三发一句「你好」

App、对象、动作，一句话里全说清了

PLAN

先把这句话，拆成三步

STEP 01启动微信
STEP 02找到会话
STEP 03输入并发送

规划步数动态收敛到 3~8 步：能三步做完，就不写五步

动手之前
先给你看

批准 重新规划
AMBIGUITY

有两个张三？

它会停下来问你，而不是替你挑一个

等你选完，再继续
SIX LAYERS

一次任务，穿过六层

01 感知 02 决策 03 转译 04 执行 05 验证 06 记忆
01 · PERCEIVE

先把屏幕，读成结构

TextView "微信" bounds=[0,180][400,240]
EditText hint="搜索" #search_box
Button "发送" #send_btn
Button "允许" #dlg_allow
ImageView — 读不到，交给视觉

无障碍服务每步重读一次，绝不沿用上一页的坐标

26 SEMANTIC IDS

26 类常见控件，被标注成语义 ID

dlg_allow ad_skip search_box send_btn confirm_btn close_btn back_btn switch_toggle

标注在端侧完成，AI 拿到的是 ID，不是让你去猜坐标

SPARSE TREE

元素树读不出东西的时候

≤3元素数小于等于三 → 判定为复杂页面强制走云端视觉
>3元素树可读 → 判定为简单页面交给端侧 3B

稀疏度本身就是路由依据，不需要再单独判断一次

VISION ROUTING

视觉能力有三个档位

CLOUD只走云端视觉
LOCAL只走端侧识别
AUTO云端失败自动回退

LOCAL 档位不依赖 API Key；稀疏元素树会强制覆盖 LOCAL

ON-DEVICE 3B

端侧模型跑得动，但不能跑飞

推理硬超时 120秒 图像编码或生成阶段超时就中断，返回 __ERR_TIMEOUT__，Kotlin 侧自动回退本地识别
并发保护 1把互斥锁 模型预热与正式识别串行执行，避免并发访问非线程安全的上下文导致数据竞争
02 · DECIDE

高频的坑，本地就填掉

弹窗 → 点允许 开屏广告 → 点跳过 加载中 → 等一下 报错页 → 点重试

这些都不消耗云端额度

端侧先判一轮，只有真需要决策的场景才上云

CONTEXT BUDGET

每一轮，模型看到的就这些

01当前页面元素树与语义 ID每步重读
02已走过的步骤与失败原因含原因前缀
03任务记忆：目标 + 你的原话独立存储
04上一步 shell 输出截断 1200 字符

装不下的截断，装得下的一字不改

03 · TRANSLATE

AI 说要什么，端侧决定怎么做

// 模型输出：意图
{ "intent": "tap",
  "target": { "by": "id", "value": "send_btn" } }
// 端侧输出：动作
{ "type": "tap",
  "x": 982, "y": 1740 }

AI 永远不输出命令，也不输出坐标

15 INTENTS

AI 只被允许说这 15 个动作

back home refresh search send confirm close share collect copy delete download add switch clear_input

端侧把它们实时转译成已有的点击 / 按键动作

COLD START

每次任务开始，先把这些清空

对话消息
失败计数
无效命令计数
上一条 shell 输出
上一页截图
上一任务计划
工作记忆

上一条任务的经验，不该污染这一条

TARGET

怎么找到那个控件

01语义 ID 精确匹配by = id
02控件文字包含匹配by = text
03元素树读不到，才用视觉坐标by = vision

找不到就先滚动查找，仍然找不到就中止，不硬猜

AUTH

权限不同，通道不同

最高权限无线 ADB / Shizuku
基础权限无障碍服务
没有权限只读，不动手

默认无线 ADB 优先；Shizuku 作为可选增强，拉起失败不阻塞任务

04 · ACT

一条命令，先走能走的那条

PRIMARYshell 命令
FALLBACK无障碍手势
TOOLCHAINTermux 命令

权限降级时自动换下一条，任务不中断

ERROR SHORTCUT

有些错，不值得再试三次

01未知的 shell 命令立即失败
02空命令立即失败
03参数非法立即失败

这类结构化错误直接跳过三次无效重试，把原因和可用命令清单注入下一轮决策

MCP SKILLS

调用外部技能，也有硬边界

单次超时 20秒 超时即放弃本次调用
输出截断 1200字符 防止大段返回值撑爆上下文
拒绝熔断 3次 连续被拒就停止任务，防死循环

调用结果作为「上一步结果」注入下一轮决策

05 · VERIFY

做完之后，还要验一遍

BEFORE7c1a 4e93 b8f2 05d6
比对
AFTERa30f 91b7 4c88 e2a1

页面指纹变了，才算真的生效

三次都没生效
就不硬试了

把方向盘交回给你，处理完点一下，它接着走

DONE CRITERIA

「做完了」不是随便说的

至少真实执行过3 步
至少走完规划步数的60%
当前页面上有明确的完成证据写进总结

连续三次过早收尾，才强制结束，防死循环

06 · REMEMBER

同一个坑，不踩第二次

FIRST遇到 → 摸索
THEN沉淀成记忆
NEXT直接复用

记忆里存的是页面指纹 + 标签 + 解法，命中就不再问模型

TASK MEMORY

记忆要认得出自己属于谁

归属判定 1个 taskId 旧任务的收尾不会把新任务标成未完成
容量上限 30条 超出后淘汰最旧的一条
去重规则 0模糊合并 你的要求按精确重复判断，绝不做相似度合并

记忆不是进度条，它保住的是目标和你的原话

SAFETY

有些页面，只许看

敏感页自动切成只读，一个动作也不做

—支付 / 银行 / 密码页切 READONLY
—手机号138****6688
—身份证号3301**********1234
—银行卡号**** **** 9021

送进模型之前，敏感字段就已经被替换掉

THREE RULES

于是它敢替你动手

意图与执行分离 端侧决策优先 每一步都经过验证
