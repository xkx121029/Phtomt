## 1. 品牌气质与视觉基调

### 1.1 一句话

**一台放在你口袋里的、会自己动手的精密工具。**

不是"又一个 AI 助手"，是"一把用得顺手、越用越放心的工具"。它安静地待在后台，替你把手机上的重复操作一步步做完；你要看的是它**做到哪一步了**，而不是它有多聪明。

### 1.2 要让人产生的三个印象

| 印象 | 靠什么支撑 | 反面（我们不要的） |
| --- | --- | --- |
| **可靠** | 深墨绿近黑的锚点色、克制的描边、稳定的 4pt 栅格 | 大量高饱和色块、闪烁的强调色 |
| **可读** | 暖纸白底 + 高对比正文、大字号标题、宽松中文行高 | 灰字铺满屏、浅灰配浅灰的"高级感" |
| **在动** | 全站只有一种亮色用于"正在执行"（流萤青 / 萤点） | 到处发光、霓虹描边、彩色渐变光晕 |

### 1.3 刻意不要像什么

1. **不要蓝紫渐变科技感。** 这是 AI 产品最省事的默认皮肤，也是最没有识别度的一层皮。本项目的品牌色是墨玉绿系（玄青），全库唯一残留的旧蓝紫渐变（页眉品牌瓦片）在 v1.0 退役。
2. **不要"玻璃拟态一窝蜂"。** 磨砂只允许出现在**真正浮在滚动内容之上的固定 chrome**（吸顶页眉、浮层）。平铺卡片用底色差与发丝线表达层级，不用半透明。理由写在 `ui/theme/Color.kt` 的 `glassTint` 注释里：玻璃的价值是"内容从中透出来"，平铺卡片背后没有内容可透，叠上去只剩一层发白的塑料膜。
3. **不要圆角卡片堆砌。** 圆角是分级语言（10 → 32dp 共 7 档），不是"所有东西都 16dp"。信息密集的页面走「工作台」风格：平铺分区 + 发丝分隔线，允许零投影。
4. **不要把星芒 / 火箭 / 大脑当品牌符号。** 这三个图形已经被用烂到不承载任何信息。品牌符号是「亮格」（见 1.4）。
5. **不要 emoji 充当图标。** 状态一律用统一的线性图标 + 语义色。

### 1.4 核心隐喻：墨 · 纸 · 萤 · 格

| 元素 | 含义 | 视觉载体 |
| --- | --- | --- |
| **墨** | 沉重、可靠、不喧哗 | 深墨绿锚点 `#063A2E`，近黑文字 `#1A1D1B` |
| **纸** | 日常、可书写、有体温 | 暖纸白 `#F7F6F3`（不是纯白） |
| **萤** | 代理"正在动"的那一点光，全站唯一的高亮 | 流萤青 `#5FD9B4`（深色）/ 玄青 `#0E7C66`（浅色） |
| **格** | 手机桌面：代理真正干活的地方 | 步骤轨道 `railIdle / railActive / railDone`、品牌标记「亮格」 |

品牌标记把「萤」和「格」合成一个图形：**桌面四格，其中一格正亮着**（见第 7 章）。那格亮着的方块，就是代理此刻正在操作的那个 app。

## 2. 色板

### 2.1 与现有深青色品牌色的关系：**沿用 + 演进，不替换**

结论先行：主色 `#0E7C66`（浅色）/ `#5FD9B4`（深色）**原样沿用**，VI 只做三件事——补齐语义槽位、明确使用边界、清退历史遗留的旧蓝。

依据：

1. **已经全链路落地，替换等于全量返工且没有收益。** 该色值出现在 10 套配色（4 套色板 × 浅/深/高对比度派生）、官网 `website/src/styles/tokens.css`、悬浮窗 `overlay/FloatingUi.kt`。换一个色号不会让产品更好认，只会让已有认知重新归零。
2. **可访问性达标。** `#0E7C66` on `#F7F6F3` = **4.75:1**，正文与按钮均过 WCAG AA；白字 on 玄青 = **5.13:1**。
3. **它本身就是"反俗套"的选择。** 墨玉绿避开了蓝紫区间，暖纸白避开了纯白，这套底色是品牌识别度最直接的来源。
4. **真正需要退役的是残留旧蓝，不是玄青。** 勘察发现两处 VI 之前的资产仍在用旧品牌：桌面图标 PNG（`ic_launcher.png` 主色为 `#1C85BF` 亮蓝）与页眉品牌瓦片（`BrandNavy #0A2E27 → Accent` 的电光蓝紫渐变）。这两处与"不要蓝紫渐变"直接冲突，v1.0 一并替换为新标记（见第 7 章）。

### 2.2 主色与辅助色

| 角色 | 浅色（纸） | 深色（夜） | 用途 | 硬约束 |
| --- | --- | --- | --- | --- |
| **玄青（主）** | `#0E7C66` | `#5FD9B4` | 主按钮、选中态、链接、进行中状态 | 浅色下不做小字号正文（4.75:1 仅够 AA） |
| 玄青深锚 | `#063A2E` | `#06231C` | 图标底、深色信息块、OG 图底 | 上面放纸白字（11.76:1） |
| 玄青容器 | `#CFEDE3` | `#17453A` | 品牌浅底块、标签底 | 字用 `#033A2F` / `#A8EBD6`，**不要**用主色当字 |
| **琥珀（暖辅）** | `#B4632A` | `#F0A868` | 需要注意但不致命的提示、时间/时长类强调 | 浅色下仅 4.08:1：**禁止**用于小于 19px 的正文，作图形/大字号或配 `onAccentWarmContainer` 使用 |
| 琥珀容器 | `#F7E3D2` | `#4E3117` | 提示条底 | 字 `#4A2410`（10.88:1） |
| **雾蓝（冷辅 / 信息）** | `#4A7C9B` | `#84B6D4` | 信息类、中性提示、次要图表 | 浅色 4.18:1，同琥珀的小字号限制 |
| 雾蓝容器 | `#DCEAF3` | `#1E3B4C` | 信息条底 | 字 `#17384C`（10.02:1） |

> 辅助色是**分工**不是**装饰**：暖=注意、冷=信息。两者都不出现在同一屏的主行动按钮上，主行动永远是玄青。

### 2.3 语义色

| 语义 | 浅色 | 深色 | 容器（浅 / 深） | 容器文字 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 成功 | `#1F7A55` | `#6FD3A2` | `#D2EDDF` / `#17452F` | `#08321F` (11.38:1) | 步骤完成、执行成功 |
| 警告 | `#9A6B12` | `#E8B75E` | `#F6E6C4` / `#4E370F` | `#38270A` (11.65:1) | 需要用户确认、降级 |
| 危险 | `#C4463C` | `#FF9A90` | `#FBDAD5` / `#6E1F17` | `#4A0F09` (11.80:1) | 失败、不可逆操作 |
| 信息 | `#4A7C9B` | `#84B6D4` | `#DCEAF3` / `#1E3B4C` | `#17384C` (10.02:1) | **复用雾蓝**，不新增色相 |

**口径**：语义色永远"实色 + 容器"成对出现。小字号（< 19px）不直接压在纸白上用裸语义色（警告 4.33:1、琥珀 4.08:1 均低于 AA 正文线），一律走"容器底 + 容器深字"。

**状态色不随配色方案变化。** 换主题（赭石 / 黛蓝 / 绛紫）时成功/警告/危险保持同一组值——状态的语义是全局的。

### 2.4 表面层级（明暗两套）

浅色（纸）——层级靠**向下压暗**：

| 层级 | 色值 | 典型用途 |
| --- | --- | --- |
| 抬升 raised | `#EDEFEA` | 卡片、列表项、分组面板 |
| 底 base | `#F7F6F3` | 页面底色 |
| 下沉 sunken | `#E3E6E0` | 输入框、代码块、内嵌凹槽 |

深色（夜）——层级靠**向上提亮**：

| 层级 | 色值 | 典型用途 |
| --- | --- | --- |
| 抬升 raised | `#1B1F1C` | 卡片、列表项 |
| 底 base | `#121513` | 页面底色 |
| 下沉 sunken | `#0C0F0D` | 输入框、代码块 |

**层级差只有 3%~6% 明度，这是刻意的。** 标准主题靠"底色差 + 发丝描边"两条腿撑层次；「无框线」主题下描边消失，代码里用 `BorderlessToneBoost = 2.0` 把色差翻倍补偿，而不是给卡片加阴影。
**阴影只在真正盖住内容时出现**（嵌入式面板 8dp、选择浮层 16dp）；正文卡片恒为 0dp，工作台风格下全站投影 no-op。

### 2.5 对比度红线

| 规则 | 阈值 |
| --- | --- |
| 正文（14–16px）与背景 | ≥ 4.5:1 |
| 大标题（≥ 24px 或 ≥ 19px 粗体） | ≥ 3.0:1 |
| 图形、图标轮廓、焦点环 | ≥ 3.0:1 |
| 弱化文字（`ink-3 #7B827B`，3.65:1） | 仅允许 ≥ 19px 或纯装饰；**不得承载信息** |

## 3. 字体层级

### 3.1 字体族

- **界面**：系统无衬线（PingFang SC / HarmonyOS Sans SC / MiSans / Source Han Sans SC → 系统 sans）。不内嵌第三方字体：中文可变字体动辄数 MB，换来的识别度远小于包体代价。
- **等宽**：仅用于代码、命令、ID、数值对齐（JetBrains Mono → Cascadia → Consolas → monospace）。
- **禁止**：把衬线体用于界面、把全大写/小型大写当作中文标注、用字重 < 400 做正文（中文细体在低 DPI 上会断笔）。

### 3.2 层级表（与 `AppTypography` 一一对应）

| 层级 | 字号 / 行高 / 字重 / 字距（em） | 中文用途 |
| --- | --- | --- |
| Display L | 57 / 64 / Bold / −0.026 | 引导页首屏主张、官网 hero |
| Display M | 45 / 52 / Bold / −0.022 | 数据大屏主数值 |
| Display S | 36 / 44 / Bold / −0.021 | 空态主标题 |
| Headline L | 32 / 40 / SemiBold / −0.016 | 页面标题 |
| Headline M | 28 / 36 / SemiBold / −0.009 | 面板标题 |
| Headline S | 24 / 32 / SemiBold / −0.004 | 卡片组标题、引导页步骤标题 |
| Title L | 22 / 28 / SemiBold / 0 | 分区标题 |
| Title M | 16 / 24 / SemiBold / +0.006 | 列表项主标题、对话框标题 |
| Title S | 14 / 20 / Medium / +0.007 | 小标题、字段名 |
| Body L | 16 / 26 / Normal / +0.0125 | 正文、说明、对话内容 |
| Body M | 14 / 22 / Normal / +0.014 | 次要正文、卡片描述 |
| Body S | 12 / 16 / Normal / +0.025 | 辅助说明（行高偏紧，仅限 1–2 行） |
| Label L | 14 / 20 / Medium / +0.007 | 按钮文字 |
| Label M | 12 / 16 / Medium / +0.025 | 徽标、标签、胶囊 |
| Label S | 11 / 14 / Medium / +0.036 | 极小标注（尽量不用） |

### 3.3 中文专用规则

1. **行高比西文宽。** 中文没有 x-height 落差，视觉上"块"更满：正文行高取 **1.6–1.7**（`bodyLarge` = 26/16 = 1.625），标题取 **1.25–1.35**，标注取 **1.35–1.45**。西文常用的 1.4 正文行高在中文里会显得挤。
2. **字距随字号反向变化，且幅度比西文小。** 汉字本身是等宽方块，负字距超过 **−0.03em** 会压到字形重心，"标题变紧"会变成"标题变糊"。大标题只做 −0.02em 级别的轻微收紧；正文字距归零到 +0.015em 之间。
3. **中西混排不额外补空格**，靠字距与行高呼吸；数字密集的表格用等宽或 `font-feature-settings: "tnum"`。
4. **断行**：中文优先按语义断（`text-wrap: pretty/balance`），标题不出现"的/了"结尾的单字孤行。
5. **不使用字重 700 以下的灰字做"高级感"**：弱化靠色阶（`ink-2` / `ink-3`）与字号，不靠降低字重。

## 4. 形状与间距

### 4.1 圆角分级（`AppRadii`，7 档，不新增数值）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `Chip` | 10dp | 状态胶囊、小徽标、筛选项 |
| `Inline` | 12dp | 内嵌小背景、紧凑控件 |
| `Tile` | 14dp | 图标瓦片、输入框、气泡尖角侧 |
| `Bubble` | 18dp | 聊天气泡、中等圆角 |
| `Item` | 20dp | 列表项、小卡片 |
| `Card` | 24dp | 分组卡片、大面板 |
| `Hero` | 28dp | 品牌区、超大容器 |
| `Overlay` / `Header` | 32dp | 对话框、手机外壳、浮动页眉 |

**规则**：内层圆角 ≤ 外层圆角（嵌套时不出现"小卡片比大卡片圆"）；同屏圆角档位不超过 3 种；胶囊（`999px`）只用于"可点的一整条"，不用于容器。

### 4.2 间距刻度（`AppSpacing`，4pt 栅格）

`2 / 4 / 8 / 12 / 16 / 20 / 24 / 32dp`

| 令牌 | 值 | 语义 |
| --- | --- | --- |
| `Xxs` | 2 | 发丝级：标题与副标题 |
| `Xs` | 4 | 图标与文字、徽章内边距 |
| `Sm` | 8 | 并列元素之间 |
| `Md` | 12 | 卡片内分行 |
| `Lg` | 16 | 卡片内边距、屏幕左右留白 |
| `Page` | 20 | 设置页/正文的栅格边距 |
| `Xl` | 24 | 分区之间 |
| `Xxl` | 32 | 整页留白、空态 |

**节奏**：卡片内边距 16，卡片之间 12，分区之间 24，页面上下 32。超过 32 的留白只在 hero 与空态出现。

### 4.3 描边策略（兼容「无框线」主题）

| 类型 | 值 | 是否受无框线开关影响 |
| --- | --- | --- |
| 装饰描边 | 1dp，`outlineSoft` 或品牌色 12% 透明度 | **是**：无框线档一律不画，层次交给 `BorderlessToneBoost` |
| 聚焦/选中描边 | 1.5–2dp，品牌色 | 否（功能语义） |
| 分隔线 | 1dp `outlineSoft`（工作台密度高时用 1px） | 是 |
| 勾选框、标尺、状态灯轮廓 | 1–2dp | 否（控件语义） |

**唯一实现点**：装饰描边必须走 `Modifier.appBorder(...)` / `appBorderStroke(...)`，不直接调 `Modifier.border` / `BorderStroke`。这样"无框线"开关才是一处生效、全站跟随。

### 4.4 尺寸令牌（`AppSize`）

触摸目标 ≥ 48dp；顶栏 56dp；标准图标 24dp，辅助图标 18dp，图标瓦片 40dp；嵌入式面板高度上限 460dp；浮层宽度上限 480dp。

## 5. 图形与图标语言

### 5.1 规范（Lucide 血统，本项目收口版）

| 参数 | 取值 |
| --- | --- |
| 网格 | 24 × 24，内容安全区 2px 内边距（即图形落在 2–22 之间） |
| 笔画 | 2.0（以 24 网格计），纯描边、无填充 |
| 端点 / 拐角 | `stroke-linecap: round`、`stroke-linejoin: round` |
| 圆角半径 | 拐角 2px 起；线条不出现 90° 硬角 |
| 视觉重心 | 图形几何中心 ≈ 12,12，允许 0.5px 光学补偿 |
| 光学对齐 | 圆形元素比方形元素外扩 0.5px（视觉等效直径） |

**缩放规则（重要）**：图标是矢量，缩放时笔画跟着等比缩。渲染尺寸 `S` 下的实际笔画 = `2 × S / 24`：

| 渲染尺寸 | 实际笔画 | 判定 |
| --- | --- | --- |
| 24dp | 2.0 | 标准，首选 |
| 20dp | 1.67 | 可用 |
| 18dp | 1.5 | 下限（`AppSize.IconSm`） |
| 16dp | 1.33 | **禁止**：低于 1.5 在高 DPI 屏上会发灰、发虚 |

需要小于 18dp 的图形时，不要缩小线性图标，改用**实心标记**（状态点、圆点、短横线）或保持 24dp 容器只画局部。

### 5.2 状态图标

| 状态 | 图形 | 色 |
| --- | --- | --- |
| 成功 / 完成 | `CircleCheck` | `success` |
| 警告 / 待确认 | `CircleAlert` / `TriangleAlert` | `warning` |
| 失败 / 危险 | `CircleX` / `CircleAlert` | `error` |
| 信息 | `Info` | `accentCool` |
| 进行中 | 呼吸圆点（`DurationPulse` 节拍） | `railActive` |

**一律单色**。彩色图标（绿勾红叉自带底色）不用于正文，只在语义胶囊里出现。
**不用 emoji 做状态。** 不用 GIF/Lottie 做状态，呼吸点靠透明度就够了。

### 5.3 现有图标如何收口

现状与结论：

1. **全部图标已经来自 Lucide 单一注册表。** 全仓 `import com.composables.icons.lucide.*` 只出现在 `ui/icons/AppIcons.kt` 一处，业务代码一律读 `AppIcons.Xxx`——这已经是理想的收口形态，VI 把它固化为硬规则：**新增图标只能加进 `AppIcons`，页面不得直接引三方图标包**。
2. **网格/笔画/端点天生合规**（Lucide 即 24 纲要 2 笔画圆端点），无需重绘。
3. **需要治理的是"尺寸滥用"**：低于 18dp 的调用点按 5.1 的缩放规则接管；图标按钮的可点区域一律 ≥ 48dp（`AppSize.TouchTarget`），描边可以细、热区不能小。
4. **品牌符号不得复用图标**：`AutoAwesome`（星芒）是通用装饰图标，不得再充当品牌标记——v1.0 起由「亮格」（第 7 章）承担。

## 6. 动效原则

### 6.1 时长分档（`Motion.kt`）

| 令牌 | 毫秒 | 用在哪 |
| --- | --- | --- |
| `DurationInstant` | 100 | 按压反馈、按下当帧的底色变化 |
| `DurationFast` | 160 | 图标切换、气泡出现、徽标 |
| `DurationNormal` | 200 | 下拉、选择器、卡片状态切换 |
| `DurationSlow` | 280 | 面板、抽屉、页面切换（上限） |
| `DurationEmphasis` | 400 | 引导页、庆祝类（一次性） |
| `DurationPulse` | 900 | 循环呼吸：运行指示、骨架、状态点 |

**上限 300ms** 是交互红线（强调类除外）；循环动效不套一次性时长，全站共用一个 900ms 节拍，否则并排的两个呼吸点会互相打架。

### 6.2 缓动分档

| 令牌 | 曲线 | 用途 |
| --- | --- | --- |
| `EaseOut` | `cubic-bezier(.23,1,.32,1)` | **入场**首选（起步快、有响应感） |
| `EaseInOut` | `cubic-bezier(.77,0,.175,1)` | 屏内位移、形变 |
| `EaseDrawer` | `cubic-bezier(.32,.72,0,1)` | 抽屉、面板上滑 |
| 线性 | — | 只给无限循环（进度条、跑马灯） |

**永不用 ease-in 做 UI**：起步慢，手感是"卡了一下"。

### 6.3 什么该动、什么不该动

| 场景 | 判断 | 做法 |
| --- | --- | --- |
| 按钮按下 | 动 | 缩放 0.97 + 12% 平涂，`Instant`，按下当帧发生，无回弹 |
| 页面/面板进入 | 动 | 从下到上，`DurationSlow` + `EaseOut` |
| 列表入场 | 动 | 逐项错开 45ms，弹簧轻微阻尼 |
| 状态切换（选中/未选） | 动 | 颜色与宽度同步过渡，`DurationNormal` |
| 高频操作（键盘、滚动、切 tab） | **不动** | 0ms，直接换 |
| 文字内容变化 | **不动** | 不做打字机、不做逐字淡入 |
| 数值跳动 | 谨慎 | 只在用户主动触发时做一次，不循环 |
| 背景/装饰 | **不动** | 无粒子、无视差、无自动旋转 |
| 回弹（bounce） | 极少 | 只给动量驱动的甩动/松手；按压一律临界阻尼 |

**动效的职责只有三件**：把"东西从哪来"讲清楚、把"状态变了"讲清楚、让"按下去了"有回应。除此之外都是噪音。

### 6.4 减少动效

系统开启"移除动画"时：呼吸类动画恒为静态常亮（不闪），位移类降为直接切换，入场保留极短淡入。所有动效实现必须读 `motionSettings().reduceMotion`，这是无障碍红线。

## 7. 品牌资产

### 7.1 品牌标记「亮格」

**手机桌面四格，其中一格正亮着。** 亮着的那格 = 代理此刻正在操作的那个 app。

构造（24 网格，可直接据此重绘）：

```
格    2 × 2 个圆角方块，单格 6.3 × 6.3，格间缝 2.7，圆角 2.0
      外框 = 2 × 6.3 + 2.7 = 15.3，居中于 24 网格（起点 4.35）
描边  1.55，round cap / round join（三格：左上、左下、右下）
实心  右上格整格填充（i = 1, j = 0）
```

- **单色**：标记只有一种颜色。纸白面上用玄青 `#0E7C66`，深锚面上用流萤青 `#5FD9B4`。
- **禁止**：加投影、加渐变、改格数、改亮格位置、旋转、把三格改成虚线。
- **最小尺寸**：16px（此时描边降到 1px 仍可辨）。
- **安全边距**：外框的 20%；瓦片内标记占瓦片宽度 60%（圆形图标占 50%）。

为什么是"格"而不是"星/光/轨迹"：星芒、光点、弯曲轨迹在 AI 产品里已经饱和且互相难以区分；四格网格是手机桌面的直接指认物，落在 24px 仍然是一个可数的结构，且天然对应 App 里的步骤轨道。

### 7.2 应用图标

| 项 | 规格 |
| --- | --- |
| 画布 | 108 × 108dp，安全区直径 66dp 圆形 |
| 背景层 | 纯色 `#063A2E`（玄青深锚），无渐变、无纹理 |
| 前景层 | 标记，色 `#5FD9B4`，外框 43.6dp，描边 4.42dp，实心格 17.96dp |
| 单色层（Android 13 主题图标） | 同几何，纯白，供系统按壁纸取色 |
| 旧版回退 PNG | 48 / 72 / 96 / 144 / 192（含 round 变体，标记占 60%） |

自适应图标的前景只有 43.6dp 宽，是因为它必须整块落在 66dp 安全圆内（外框对角半径 32.5dp）。这是 Android 规范决定的，不是"图标做小了"。

**为什么不放手机轮廓**：图标在 48dp 下只有 48 个像素可分配，任何"手机 + 屏幕 + 光点"的三层复合都会糊成一团。四格是唯一在 24dp 通知栏仍能数清的解法。

### 7.3 官网资产

| 资产 | 规格 | 用途 |
| --- | --- | --- |
| `favicon.svg` / `favicon.png` | SVG 优先 / 48px 回退 | 浏览器标签页 |
| `favicon-32.png` | 32 × 32 | 旧浏览器回退 |
| `apple-touch-icon.png` | 180 × 180 | iOS 添加到主屏（满幅、无透明、系统自己切圆角） |
| `logo-mark.svg` / `logo-mark.png` | 矢量 / 96px | 站内导航标记（显示 28px，优先 SVG） |
| `logo-glyph.svg` | 透明底单色 | 浅色面上的无瓦片版本 |
| `og-cover.png` | 1200 × 630 | 社交分享卡（`index.html` 已接 og / twitter 元信息） |

网站标记与桌面图标**同源同形**：用户从浏览器到桌面看到的必须是同一个符号。

### 7.4 可复用标记

- Web：`website/public/logo-mark.svg`（带瓦片）、`logo-glyph.svg`（透明单色）
- App：`com.phoneagent.ui.components.BrandMark`（Compose Canvas，几何常量与 SVG / VectorDrawable 同源）
- 五份实现必须同步修改：`BrandMark.kt`、`ic_launcher_foreground.xml`、`ic_launcher_monochrome.xml`、`logo-mark.svg`、`favicon.svg`
- **改完必须跑** `python tool/verify_brand_mark.py`：脚本把五份读成"相对外框"的归一化坐标，逐项比对格宽、缝宽、圆角、描边、四格位置与实心格，以及深锚/标记色/单色层三组配色，漂移即非零退出

## 8. 落地与对照

### 8.1 令牌对照表

| VI 项 | App 代码 | 官网 CSS |
| --- | --- | --- |
| 主色 | `AppColors.brand` | `--brand` |
| 主色深锚 | `BrandAnchor`（#063A2E） | `--brand-deep` |
| 容器/浅底 | `AppColors.brandContainer` | `--brand-wash` |
| 暖辅 | `AppColors.accentWarm` | `--amber` |
| 冷辅/信息 | `AppColors.accentCool` | `--mist` |
| 语义色 | `AppColors.success / warning / error` | `--ok / --warn / --danger` |
| 面层级 | `surfaceBase / surfaceRaised / surfaceSunken` | `--paper / --paper-raised / --paper-sunken` |
| 描边 | `outlineStrong / outlineSoft` + `appBorder()` | `--line / --line-2` |
| 圆角 | `AppRadii.*` | `--r-xs … --r-2xl / --r-float` |
| 间距 | `AppSpacing.*` / `AppSize.*` | `--gutter` + 4pt 手写值 |
| 字体层级 | `AppTypography.*` | `--t-display … --t-xs` |
| 动效 | `Duration* / Ease*` | `--dur-* / --ease-*` |
| 品牌标记 | `BrandMark` / `BrandMarkTint` | `logo-mark.svg` / `favicon.svg` |

**一处刻意保留的偏差**：官网 `--amber: #a85a24`、`--mist: #3f7292` 比端侧的 `#B4632A` / `#4A7C9B` 各深一档。原因是站点把这两个色直接当**文字色**用过（`base.css` 的提示行、更新日志分区标记），裸色压纸白在小字号下必须 ≥ 4.5:1，而端侧的辅助色按第 2.3 条只用于图形与成对的容器块。这不是没对齐，是同一规则在两种用法下的两个落点。

### 8.2 可回退、可对照

1. **配色方案可切**：`ThemePalette` 四套（玄青/赭石/黛蓝/绛紫），玄青为默认。VI 只约束玄青（品牌态），其余三套是用户偏好，不与 VI 冲突。
2. **无框线可切**：`LocalAppBorders` 一处开关，装饰描边全站跟随；VI 的描边策略同时兼容两档。
3. **界面风格可切**：`UiStyle.CLASSIC / WORKBENCH` 只换圆角取值口径与色调位移，不改色板。
4. **官网深浅**：`html[data-theme]` + CSS 变量，与 App 的明暗两套一一对应。
5. **资产对照**：新旧图标文件同名同尺寸，仅内容替换；如需回退，`git checkout` 单个文件即可还原，不牵动代码。
6. **品牌标记回退**：`BrandTile` 的旧实现（`Brush.linearGradient(BrandNavy, Accent)` + `AppIcons.AutoAwesome`）在 git 历史里；但 VI 明确禁止该渐变，不建议回退。
7. **几何可校验**：`tool/verify_brand_mark.py` 以 `BrandMark.kt` 常量为规范来源，比对五份实现的归一化几何与配色；容差 2e-3（外框=1），比取整误差宽、比任何真实改动窄一个量级。
