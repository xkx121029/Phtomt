## 第二部分：问题详情与修复建议

### C1【高】截屏前台服务 startForeground 未指定类型 → Android 14+ 崩溃
- 位置：[ScreenSharingService.kt L70-78](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/screen/ScreenSharingService.kt#L70-L78)（`onStartCommand` 内 `startForeground(NOTIF_ID, buildNotification())`）；Manifest 声明见 [AndroidManifest.xml L49-52](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/AndroidManifest.xml#L49-L52)（`android:foregroundServiceType="mediaProjection"`）。
- 问题：targetSdk 35（≥34）下，服务在 Manifest 中声明了 `foregroundServiceType`，但启动时调用的是不带 type 的 `startForeground(id, notification)`。按 Android 14 行为，系统会抛 `MissingForegroundServiceTypeException`，服务在 `onStartCommand` 中崩溃，MediaProjection 截屏功能在 Android 14+ 设备上完全不可用。对比同项目 [FloatingWindowService.kt L105-110](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/floating/FloatingWindowService.kt#L105-L110) 正确使用了 `ServiceCompat.startForeground(..., FOREGROUND_SERVICE_TYPE_SPECIAL_USE)`。
- 修复：改为 `ServiceCompat.startForeground(this, NOTIF_ID, buildNotification(), ServiceInfo.FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION)`（需 `import androidx.core.app.ServiceCompat` 与 `android.content.pm.ServiceInfo`）。

### C2【中】版本号自增副作用写在 Gradle 配置阶段
- 位置：[app/build.gradle.kts L14-21](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/build.gradle.kts#L14-L21)
- 问题：代码位于 `android {}` 块顶层（项目配置/评估阶段），每次 Gradle 配置——包括 IDE 同步、`gradlew tasks`、`gradlew help`、任何任务执行——都会读 `version.properties`、+1 并写回。后果：a) 未真正构建也递增版本号；b) 构建失败后版本号已消耗；c) 配置阶段写文件属副作用，与"配置可缓存"模型冲突，多进程（IDE+CLI）并发时可能相互覆盖。
- 修复：将自增逻辑移入 Gradle Task（如 `tasks.register("bumpVersion")`，由 `preBuild` 依赖），或改在 `assemble`/`bundle` 系列任务的 `doFirst` 中执行，且仅在需要生成发布版本时触发。

### C3【中】gradle.properties 硬编码本机 JDK 路径
- 位置：[gradle.properties L1](file:///d:/xkx/xkx_appproj/happy_phone%20agent/gradle.properties#L1)（`org.gradle.java.home=C:\Program Files\Microsoft\jdk-17.0.19.10-hotspot`）
- 问题：绝对路径被固化在版本库中。其他开发者/CI 环境、或本机 JDK 路径变化后，Gradle 会因找不到该路径直接报错无法构建。属可移植性缺陷。
- 修复：删除该行，改用环境变量 `JAVA_HOME` 或系统默认 JDK；若必须固定版本，改在 `gradle.properties` 之外（如 CI 环境变量 / 本地 user home 的 `~/.gradle/gradle.properties`）配置。

### C4【低】roundIcon 资源引用错误
- 位置：[AndroidManifest.xml L21](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/AndroidManifest.xml#L21)（`android:roundIcon="@mipmap/ic_launcher"`）
- 问题：项目 mipmap 目录同时提供 `ic_launcher` 与 `ic_launcher_round`，但 roundIcon 引用的是方形 `ic_launcher`，圆形启动器上会以方形裁切展示。
- 修复：改为 `android:roundIcon="@mipmap/ic_launcher_round"`。

### C5【低】specialUse 前台服务 subtype 属性缺少包名命名空间
- 位置：[AndroidManifest.xml L58-60](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/AndroidManifest.xml#L58-L60)（`android:value="agent_progress_overlay"`）
- 问题：Android 14 规范要求 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` 的值使用与包名关联的命名空间（如 `com.phoneagent.agent_progress_overlay`），裸字符串不满足合规要求（主要影响应用商店审核，运行不报错）。
- 修复：将 value 改为带包名前缀的字符串，如 `com.phoneagent.agent_progress_overlay`。
