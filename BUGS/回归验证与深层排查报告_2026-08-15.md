## 第二部分：问题代码位置与修复建议

### S1 — ScreenSharingService 位图回收竞态

- 位置：`screen/ScreenSharingService.kt` L104-107
- 问题代码：
  ```kotlin
  latestFrame?.recycle()
  latestFrame = image.toBitmap()
  ```
- 说明：`latestFrame` 被捕获线程回收，但 `AgentEngine.run`（L652）与 `observe()`（L1115）取到的引用随后在 `Dispatchers.IO` 的 `base64Image()` 中被读取；`@Volatile` 只保证可见性，不保证位图生命周期。
- 修复建议：
  1. `captureFrame()` 改为返回**拷贝**（`latestFrame?.copy(...)`），或
  2. 引入引用计数 / 在回收前检查"是否有消费者"（如加 `synchronized` + `inUse` 计数），或
  3. 先 `image.toBitmap()` 成功后再回收旧帧，并把 `latestFrame = new` 与 `old?.recycle()` 放同一临界区，避免异常时残留已回收位图。

### H1 — ScreenSharingService 旋转适配未实现（回归失败）

- 位置：`screen/ScreenSharingService.kt` L61、L93-121、L131
- 说明：`displayListener` 仅声明并在 `onDestroy` 注销，全工程无 `registerDisplayListener` 调用、无旋转后重建 `VirtualDisplay/ImageReader` 的代码。上一轮"修复了旋转适配（DisplayListener）"并未落地。
- 修复建议：在 `startProjection` 中注册 `DisplayManager.DisplayListener`，`onDisplayChanged` 时读取新 `getRealSize`，释放旧 `ImageReader/virtualDisplay` 并重建，同时把新尺寸同步给 `AgentEngine` 的 `screenWidth/Height`（当前 `lastSnapshot` 是旧尺寸）。

### H2 — AiClient.chatStream onDelta 跨重试重复

- 位置：`ai/AiClient.kt` L364-402
- 说明：`full.setLength(0)` 在每次尝试开始处重置，只修正了返回值；但第一次失败尝试已通过 `onDelta` 发给调用方（`AgentEngine.cloudPlanStream` L257、`TestEngine.runPreset` L158）的增量无法撤回，重试后再次全量推送 → UI 重复。
- 修复建议：方案 A（推荐）：首次失败不再重试，直接抛错让上层重来；方案 B：重试前先通过回调告知调用方回滚（不现实）；方案 C：把 `onDelta` 改为携带"是否清理"信号。最稳妥是 A —— 流式场景对实时性要求高，中断重试反而引入重复，交由上层整段重试更简单。

### H3 — DebugScreen LazyColumn 重复 key

- 位置：`ui/debug/DebugScreen.kt` L213、L321
- 说明：`key = "${it.timestamp}:${it.role}"`、`key = "${it.timestamp}:${it.message}"`。`AgentEngine.log`（L214）在同毫秒内连续追加多条日志（决策循环内多次 `log()`）时 key 碰撞 → LazyColumn 抛异常崩溃。
- 修复建议：追加单调递增序号作为 key（如 `"$timestamp-$index"`），或直接使用 `key = { it }`（List 自带 index）去掉自定义 key；Conversation 可加自增 id 字段。

### H4 — SettingsScreen 预览与运行中光效冲突

- 位置：`ui/settings/SettingsScreen.kt` L92-106；`MainActivity.kt` L140-155
- 说明：`EdgeLightingService` 为单实例；Agent 运行中若展开标定（`startPreview`）再收起（`stopPreview`），`stopPreview` 执行 `removeOverlay + stopSelf` 会把运行中任务的光效一起关掉；MainActivity 的 `LaunchedEffect(agentState.isRunning, ...)` 键值不变不会重新 `start`。
- 修复建议：`stopPreview` 改为仅切换预览模式（`setPreviewMode(false)` + `updateCalibration`）而不 `stopSelf`；由 MainActivity 的 `LaunchedEffect` 统一负责"任务是否运行"的启停决策，设置页只负责预览态切换。

### M1 — AgentEngine resolvePoint 坐标未 clamp

- 位置：`agent/AgentEngine.kt` L1029-1034
- 说明：`coordinate` 方法返回 `(parts[0]!! * screenWidth()).toInt()`，未对结果做 `coerceIn(0, screenWidth())` 等边界处理。
- 修复建议：`(parts[0]!! * screenWidth()).toInt().coerceIn(0, screenWidth())`，y 同理。

### M2 — AgentEngine swipeEndpoints 水平滑动距离错误

- 位置：`agent/AgentEngine.kt` L1038-1047
- 说明：`val dist = screenHeight()` 对所有方向生效，`left/right` 应使用 `screenWidth()`。
- 修复建议：按方向分别取 `screenWidth()`/`screenHeight()`。

### M3 — EdgeLightingView 零尺寸退化 NaN

- 位置：`edge/EdgeLightingView.kt` L408-483（`getPointOnBorder`）、L155-165（`colorAtDist`）
- 说明：`radius` 修复已解决正常布局；但视图尺寸为 0（首次 onDraw 前）时 `segTop=0` 且 `distance=0` → `0/0 = NaN`。
- 修复建议：在 `onDraw` 开头 `if (w <= 0f || h <= 0f) return` 提前退出；`colorAtDist` 对 `totalPath <= 0` 直接返回首色。

### M4 — AiClient.parseCoordinate 围栏解析失败

- 位置：`ai/AiClient.kt` L320-332
- 说明：`removePrefix("```")` 后残留 `json\n`，无法 parse；逗号兜底 split 也失败。
- 修复建议：先剥掉 ```json``` 围栏（复用 `extractJson` 逻辑或先 `replace("```json","")` 再处理），再解析。

### M5 — AiClient 缩放位图未回收

- 位置：`ai/AiClient.kt` L567-583
- 说明：`scaleBitmap` 新建的位图从不 recycle。
- 修复建议：`base64Image` 内对缩放结果 `finally { if (scaled !== src) scaled.recycle() }`。

### L1/L2 — 关键词启发式误判

- 位置：`perception/PageAnnotator.kt` L28-30、L62-68；`decision/LocalDecisionEngine.kt` L53-67
- 建议：把 `"x"` 改为精确匹配（label.trim() == "x"）或删除；`"ok"` 改为 `"ok"` 需单词边界/仅在英文短 label 匹配；`hasCount` 改为"任一无 label 含数字 + 任一 label 含倒计时词"（两条件分离判定）。

### L3 — ShellCommands toPixel 1.0 歧义

- 位置：`agent/ShellCommands.kt` L164-174
- 建议：对比例输入限定 `0f < f < 1f`，`f == 1.0` 视为比例（全屏）更符合 AI 坐标习惯；或要求比例必须带小数点（`1.0`），像素整数必须 `>=2`。

### L4 — FloatingWindowService ACTION_STOP 死代码

- 位置：`floating/FloatingWindowService.kt` L133、L561
- 说明：`stop()`（L576-579）已改为 `stopService`，全工程无任何位置发送 `ACTION_STOP` 或 `"stop"` extra。
- 建议：保留 `onStartCommand` 兜底无妨，但可在后续清理死代码；确认无其他模块依赖此 action（已验证：grep 全工程仅本文件两处引用）。

### L5 — 无障碍节点回收与递归深度

- 位置：`a11y/AgentAccessibilityService.kt` L85、L140-146；`a11y/ActionExecutor.kt` L108-139
- 建议：`ActionExecutor` 的 `findNodeAt/findFirstEditable` 增加深度上限（如 80）并在 API<33 下对 `getChild` 结果 `recycle()`；`collectElements` 的 root 节点在 API<33 下由调用方 `recycle()`。

### L6 — AgentEngine 跨任务状态残留

- 位置：`agent/AgentEngine.kt` L149、L708、L318
- 建议：`start()`/`processQueue` 开始时重置 `consecutiveFailures`；`approvePlan` 若 `job` 活跃则先取消旧任务再启动新任务（或提示用户）。
