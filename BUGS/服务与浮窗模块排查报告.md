## 第二部分：问题详情与修复建议

### B1【高】截屏 Bitmap 不回收 → 内存持续增长 OOM
- 位置：[ScreenSharingService.kt](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/screen/ScreenSharingService.kt#L95-L101)（onImageAvailableListener）、[L151-161](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/screen/ScreenSharingService.kt#L151-L161)（Image.toBitmap）
- 问题：每次 `acquireLatestImage` 都新建全屏 `Bitmap.createBitmap(...)` 并赋给 `latestFrame`，旧 Bitmap 从未 `recycle()`。Agent 每轮观察都取帧，全屏 1080×2400×4B ≈ 10MB/帧，长时间运行内存只增不减直至 OOM。`latestFrame` 也非 volatile，跨线程读写存在数据竞争。
- 修复：替换前 `latestFrame?.recycle()`；或复用同一个 Bitmap 画布；`onDestroy` 回收当前帧；`latestFrame` 加 `@Volatile`。

### B2【高】后台启动悬浮窗前台服务无保护 → 任务循环崩溃
- 位置：[AgentEngine.kt](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/agent/AgentEngine.kt#L164-L168)（maybeStartFloating）、[L636](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/agent/AgentEngine.kt#L636)（调用点）、[L528-535](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/agent/AgentEngine.kt#L528-L535)（processQueue）、[FloatingWindowService.kt L565-567](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/floating/FloatingWindowService.kt#L565-L567)
- 问题：`run()` 在 `Dispatchers.Default` 协程里调用 `FloatingWindowService.start()`（内部 `startForegroundService`），外层 `processQueue` 循环未包 try-catch。多任务队列、锁屏、切后台后若悬浮窗已停止且新任务开始，Android 12+ 抛 `ForegroundServiceStartNotAllowedException`，异常冒泡终止协程：剩余任务不再处理、`_state.isRunning` 不重置、任务队列卡死。
- 修复：`maybeStartFloating` 内用 `runCatching` 包裹 `startForegroundService`；`processQueue` 中 `run` 包 try-catch 兜底；悬浮窗服务改为应用启动时常驻，仅首次前台创建。

### B3【中】后台用普通 `startService` 停止悬浮窗 → IllegalStateException
- 位置：[FloatingWindowService.kt L569-571](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/floating/FloatingWindowService.kt#L569-L571)；调用方 [AgentEngine.kt L511](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/agent/AgentEngine.kt#L511)、[L324](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/agent/AgentEngine.kt#L324)、[MainViewModel.kt L97](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/ui/MainViewModel.kt#L95-L99)
- 问题：`stop()` 用 `context.startService(intent)`。App 在后台（任务结束、VM onCleared、协程失败分支）调用时，Android 8+ 抛 `IllegalStateException: Not allowed to start service`。
- 修复：改为 `context.stopService(intent)`（停止已运行服务，不触发创建）或直接 `ScreenSharingService.instance` 式的 `FloatingWindowService.instance?.stopSelf()`；对后台场景统一用实例方法停止。

### B4【中】悬浮窗无旋转/多窗口适配，旋转后可能出屏不可见
- 位置：[FloatingWindowService.kt L147-157](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/floating/FloatingWindowService.kt#L147-L157)（x=dp(160)/y=dp(180) 固定）、[L551](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/floating/FloatingWindowService.kt#L551)（dp）
- 问题：窗口位置相对整屏固定，屏幕旋转/分屏后坐标系变化，悬浮窗可能整体移出屏幕或与状态栏重叠，且无任何回调重新定位。
- 修复：重写 `onConfigurationChanged`，用 `WindowMetrics`（API 30+，否则 `getRealSize`）获取新屏幕尺寸，将 x/y clamp 到安全区内；初始化时同样用实际屏幕宽高计算初始位置。

### B5【中】屏幕旋转后截屏尺寸不更新 → 视觉定位错位
- 位置：[ScreenSharingService.kt L87-113](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/screen/ScreenSharingService.kt#L87-L113)
- 问题：`startVirtualDisplay` 用启动时屏幕尺寸创建 ImageReader/VirtualDisplay，无任何 Configuration 监听。旋转后真实屏幕方向变化，但 virtual display 仍是旧尺寸，截图像素与真实 UI 不匹配，Agent 视觉模型返回的比例坐标换算后全部点错位置。
- 修复：注册 Configuration 回调，方向变化时 `virtualDisplay?.release()` / `imageReader?.close()` 并用新尺寸重建；或改用随旋转自适应的 SurfaceView 方案。

### B6【中】元素树递归无上限且节点不回收 → StackOverflow / 内存泄漏
- 位置：[AgentAccessibilityService.kt L102-144](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/a11y/AgentAccessibilityService.kt#L102-L144)（collectElements）、[ActionExecutor.kt L108-139](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/a11y/ActionExecutor.kt#L108-L139)（findNodeAt / findFirstEditable）
- 问题：`collectElements` 与 `findNodeAt/findFirstEditable` 递归遍历整棵窗口树，无深度/节点数上限、无去重。WebView/超长列表场景可致 StackOverflowError（直接杀死任务协程）；API<33 上 `getChild()` 返回的节点未 `recycle()` 造成内存泄漏；每次观察全量遍历耗时。
- 修复：增加最大深度与最大节点数（如 64/300）剪枝；访问过的 node 集合去重；API<33 时对子节点 `recycle()`；遍历放在后台线程并做超时保护。

### B7【中】EdgeLightingView 分段长度归零导致除零 → NaN 坐标
- 位置：[EdgeLightingView.kt L407-482](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/edge/EdgeLightingView.kt#L407-L482)，尤其是 [L419-422](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/edge/EdgeLightingView.kt#L419-L422) 与 [L470-474](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/edge/EdgeLightingView.kt#L470-L474)
- 问题：`segTop = w - 2*radius`、`segLeft = h - 2*radius`。当标定 `cornerRadius ≥ min(w,h)/2`（onDraw 中 radius 被 clamp 到 `min(w,h)/2`）时 `segTop`/`segLeft` 为 0，`d / segTop = 0/0 = NaN`，光点坐标为 NaN，渲染异常。设置页大圆角标定即可复现。
- 修复：对 `segTop/segRight/segBottom/segLeft` 做 `if (seg <= 0f)` 短路返回；或 clamp 段长最小值。

### B8【低】动画每帧分配对象 → GC 卡顿
- 位置：[SuccessMarkView.kt L103-111](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/floating/SuccessMarkView.kt#L103-L111)（每帧 new LinearGradient + Path）、[EdgeLightingView.kt L202-282 / L333-338](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/edge/EdgeLightingView.kt#L202-L282)（drawSegmentedBorder 每段 new 着色器）
- 问题：动画驱动期间（全屏 60fps）高频创建 LinearGradient/Path，主线程 GC 压力大、易掉帧、耗电。
- 修复：尺寸/颜色不变时缓存 LinearGradient 与 Path 复用；`onSizeChanged`/`setCalibration` 时重建。

### B9【低】MarqueeView 动画在 detached/GONE 后不停止
- 位置：[MarqueeView.kt L57-65、L89](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/floating/MarqueeView.kt#L57-L65)
- 问题：`running` 一旦为 true 永不复位，任务结束后 view 被 GONE 或从窗口移除仍持续 `postInvalidateOnAnimation`，造成无意义的绘制调度。
- 修复：重写 `onDetachedFromWindow` 置 `running=false`；GONE 时停止；增加 `stop()` 供 resetPanel 调用。

### B10【低】EdgeLightingService 重启后无条件重建全屏光效
- 位置：[EdgeLightingService.kt L69-83、L82](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/edge/EdgeLightingService.kt#L69-L83)
- 问题：该服务非前台服务、无通知保护，`onStartCommand` 返回 `START_STICKY`。系统回收后以 null Intent 重启走 else 分支 → `showOverlay()` 无条件重建全屏边缘光效。此时任务可能早已结束（MainActivity 已发 stop），光效却再次弹出且无关闭入口。
- 修复：改为返回 `START_NOT_STICKY`；或记录"服务应由谁驱动"，null Intent 时直接 `stopSelf()`；任务停止时主动销毁。

### B11【低】Shizuku 权限回调可能永不触发 / 线程问题
- 位置：[ShizukuManager.kt L58-73](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/shizuku/ShizukuManager.kt#L58-L73)
- 问题：`requestPermission` 注册 listener 后若 Shizuku 进程被杀/无响应，`onResult` 永不回调，调用方永久挂起；回调运行在 Binder 线程，直接回传 UI（Compose state）存在跨线程更新风险。
- 修复：增加超时与 `Shizuku.pingBinder()` 状态检查，失败时回调 false；`onResult` 内切到主线程（`Handler(Looper.getMainLooper())`）。

### B12【低】dispatchGesture 协程无取消钩子
- 位置：[ActionExecutor.kt L142-157](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/a11y/ActionExecutor.kt#L142-L157)
- 问题：`suspendCancellableCoroutine` 未注册 `cont.invokeOnCancellation`，任务被 `stop()` 取消时正在派发的手势无法显式取消，回调会访问已取消的 continuation。
- 修复：`cont.invokeOnCancellation { /* 记录取消，回调按 isActive 忽略 */ }`，必要时在取消时关闭手势。

### B13【低】拖动时向 updateViewLayout 传可空 root
- 位置：[FloatingWindowService.kt L359](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/floating/FloatingWindowService.kt#L359)
- 问题：`windowManager?.updateViewLayout(root, p)` 中 `root` 为可空属性（平台类型参数编译放行），若拖动瞬间服务销毁（`root=null`）会 NPE 崩溃。
- 修复：`onTouchDrag` 开头 `val r = root ?: return false`，后续使用 `r`。

### B14【低】自启动权限检测语义不等价
- 位置：[MainViewModel.kt L162、L179-182](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/ui/MainViewModel.kt#L179-L182)
- 问题：AUTOSTART 项用 `isIgnoringBatteryOptimizations` 判定"自启动/省电白名单已开启"，二者并非同一授权，部分厂商机型会误报已授权。
- 修复：改为按厂商跳转页的可用性/或直接标注"需手动确认"；对 Xiaomi/Huawei 等通过 resolveActivity 检测后展示未授权。
