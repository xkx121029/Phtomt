## 一、项目概述

**Happy Phone Agent（快乐手机助手）** 是一款基于 Android 的 AI 手机自动化 Agent 应用。核心能力：用户输入自然语言任务描述，AI 读取手机屏幕，自动完成操作（点击、输入、滑动、打开应用等）。

**技术栈：**
- Kotlin + Jetpack Compose（Material 3 Expressive UI）
- Koin DI + DataStore 持久化
- 独立权限 Provider（`:provider` APK，经 AIDL 提供服务）+ 主应用内无障碍服务
- Shizuku（内嵌 server，随 Provider 打包）+ 无线 ADB + Termux 三条 shell 通道
- OpenAI 兼容 AI API（GLM 等）
- 双通路视觉：端侧 3B 模型（JNI）+ 云端视觉模型

**代码规模：** 266 个主工程 Kotlin 源文件 + 67 个单元测试文件（737 个用例）；核心 AgentEngine 约 3390 行
（已按阶段拆出 runtime / execution / planning / decision / context 等子包，主类只留主循环骨架）。

**模块划分（Gradle 多模块）：**

| 模块 | 职责 |
|------|------|
| `:app` | 主应用（UI / 引擎 / 记忆 / 悬浮窗），不含系统权限代码 |
| `:provider` | 独立权限服务 APK：无障碍服务、内置 Shizuku server、无线 ADB、Termux 桥 |
| `:provider-api` | 跨进程契约（AIDL `IDeviceProvider` + Parcelable），两端共用同一份定义 |
| `:shizuku-*`（9 个） | vendor 自 RikkaApps/Shizuku 的客户端与 server 源码，供 `:provider` 内嵌 |

## 三、核心数据模型

### 3.1 AgentIntent — AI 输出的意图

AI 在 JSON 中输出的意图，描述"做什么"和"对什么做"：

```kotlin
data class AgentIntent(
    val intent: String,              // 意图类型（open_app/tap/input/...）
    val target: AgentIntentTarget?,  // 目标 { by: "text", value: "发送" }
    val app: String?,                // 应用名/包名
    val text: String?,               // 输入文字
    val direction: String?,          // 滑动方向
    val waitMs: Long?,               // 等待时长（ms）
    val reasoning: String?,          // AI 思考过程
    val expected: String?,           // 执行后预期
    val confidence: Double?,         // 置信度 0~1
    val pageFingerprint: String?,    // 页面指纹
    val needsConfirmation: Boolean,  // 是否需用户确认
)
```

### 3.2 AgentAction — 端侧内部动作命令

转译层输出，描述"怎么做"：

```kotlin
data class AgentAction(
    val type: String,          // 动作类型（launch/tap/type/...）
    val x: Int?, val y: Int?, // 像素坐标
    val target: ActionTarget?, // 目标描述 {method, value}
    val packageName: String?,  // 应用包名
    val command: String?,      // shell 命令（Shizuku 模式）
    val reason: String?,       // 用户可见的执行说明
    val reasoning: String?,    // AI 思考过程
    val expected: String?,     // 预期结果（验证对比用）
    val pageFingerprint: String?, // 页面指纹
)
```

### 3.3 AgentState — Agent 运行状态

```kotlin
data class AgentState(
    val isRunning: Boolean,
    val task: String,
    val phase: Phase,       // IDLE → OBSERVING → THINKING → ACTING → DONE/ERROR
    val message: String,
    val stepCount: Int,
    val lastAction: AgentIntent?,
)
```

## 四、完整执行流程

### 阶段一：任务规划

```
用户输入任务描述（如"打开微信给张三发'你好'"）
        │
        ▼
┌─ 模板匹配 ──────────────────────────────────────────────┐
│ TaskStore.searchSimilarTasks(task)                      │
│   ├─ 命中历史模板 → 直接展示计划，等待用户批准           │
│   └─ 未命中 → 进入 AI 规划                              │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─ AI 流式规划 ───────────────────────────────────────────┐
│ CloudAgent.planStream(task)                             │
│   ├─ 调用 AI API（temperature=0.3）流式输出计划          │
│   ├─ 歧义检测：AI 识别不确定点 → 生成澄清问题            │
│   │     └─ 悬浮窗弹出澄清面板 → 用户选择 → 重新规划     │
│   └─ 生成 TaskPlan（步骤列表 + 每步意图）                │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─ 用户批准 ──────────────────────────────────────────────┐
│ 悬浮窗展示计划摘要                                       │
│   ├─ 用户批准 → 进入执行循环                            │
│   └─ 用户拒绝/修改 → 返回重新规划                       │
└─────────────────────────────────────────────────────────┘
```

### 阶段二：ReAct 执行循环（每步）

```

│  │    └─ 构建 ScreenSnapshot                          │   │
│  │                                                    │   │
│  │  PageAnnotator.annotate(snapshot)                  │   │
│  │    ├─ 推断页面类型（search_page/product_detail/...）│   │
│  │    ├─ 生成上下文提示（"这是一个搜索结果页"）        │   │
│  │    └─ 标注控件优先级（high/medium/low）            │   │
│  │                                                    │   │
│  │  安全检查：SensitivePageDetector.isSensitive()     │   │
│  │    └─ 支付/银行/私密页面 → 强制 READONLY 模式      │   │
│  │                                                    │   │
│  └────────────────────────────────────────────────────┘   │
│                          │                               │
│                          ▼                               │
│  ┌─ Step 2: 本地决策（Local Decision）─────────────────┐  │
│  │                                                     │  │
│  │  LocalDecisionEngine.decide(snapshot)               │  │
│  │    ├─ dialog_overlay → 自动点击"允许/确定"          │  │
│  │    ├─ ad_with_countdown → 自动跳过广告              │  │
│  │    ├─ loading → wait 1200ms                         │  │
│  │    ├─ error → 点击"重试"                            │  │
│  │    └─ completion（元素≤5）→ finish                  │  │
│  │                                                     │  │
│  │    若无法本地处理 → 返回 null，走云端决策            │  │
│  │    连续 N 次本地决策 → 强制走云端（防死循环）        │  │
│  │                                                     │  │
│  └─────────────────────────────────────────────────────┘  │
│                          │                               │
│                          ▼ (null = 走云端)               │
│  ┌─ Step 3: AI 决策（AI Decision）─────────────────────┐  │
│  │                                                     │  │
│  │  视觉定位（如需）：                                  │  │
│  │    ├─ 外挂 3B 端侧模型（ExternalVisionProvider）     │  │
│  │    │     timeout=20s → 超时回退云端                 │  │
│  │    └─ 云端视觉模型（AiClient.visionLocate）          │  │
│  │        → 返回视觉坐标 (x, y)                         │  │
│  │                                                     │  │
│  │  CloudAgent.decideStream(snapshot, context)          │  │
│  │    ├─ 构造 prompt（含页面类型/上下文/历史步骤）       │  │
│  │    ├─ 流式调用 AI API（temperature=0.1）            │  │
│  │    ├─ 稳健 JSON 解析（extractJsonObject + 重试）     │  │
│  │    ├─ 超时保护（WATCHDOG_DECIDE_MS=45s）             │  │
│  │    └─ 反序列化 → AgentIntent                        │  │
│  │                                                     │  │
│  │  异常记忆查询（AnomalyMemoryEngine）：               │  │
│  │    指纹/标签命中 → 复用历史解决方案（跳过 AI 调用）  │  │
│  │                                                     │  │
│  └─────────────────────────────────────────────────────┘  │
│                          │                               │
│                          ▼                               │
│  ┌─ Step 4: 意图转译（Translation）────────────────────┐  │
│  │                                                     │  │
│  │  IntentTranslator.translate(intent, snapshot, visual)│  │
│  │    │                                                 │  │

│  │    │     IntentType.TO_ACTION[intent] → ActionType   │  │

│  │    │                                                 │  │

│  │    │     AppNameResolver.resolve("微信")             │  │
│  │    │     → "com.tencent.mm"（运行时搜索已安装应用）   │  │
│  │    │                                                 │  │
│  │    ├─ 5. 通道选择（按授权模式）                        │  │
│  │    │     SHIZUKU    → type="shell", command="launch" │  │
│  │    │     ACCESSIBILITY → type="launch"               │  │
│  │    │     READONLY   → Failed（除 wait/write_doc）    │  │
│  │    │                                                 │  │
│  │    └─ 输出 AgentAction                               │  │
│  │                                                     │  │
│  └─────────────────────────────────────────────────────┘  │
│                          │                               │
│                          ▼                               │
│  ┌─ Step 5: 带验证执行（Verified Execution）───────────┐  │
│  │                                                     │  │
│  │  executeWithVerify(action, snapshot)                │  │
│  │    │                                                 │  │
│  │    ├─ 执行动作：                                     │  │
│  │    │     launch   → executor.launchApp(pkg)          │  │
│  │    │     tap      → executor.click(x, y)             │  │
│  │    │     long_press → executor.longClick(x, y)       │  │
│  │    │     type     → executor.typeText(text, target)  │  │
│  │    │     swipe    → executor.swipe(x1,y1,x2,y2)      │  │
│  │    │     key      → executor.back/home/recents()     │  │
│  │    │     wait     → delay(timeoutMs)                 │  │
│  │    │     shell    → ShizukuManager.exec(command)     │  │
│  │    │     scroll   → executor.scroll(elem, direction) │  │
│  │    │     task_done → 标记完成                        │  │
│  │    │                                                 │  │
│  │    ├─ 页面指纹验证（PageFingerprint）：               │  │
│  │    │     fingerprintAfter = PageFingerprint.compute()│  │
│  │    │     对比 fingerprintBefore vs After             │  │
│  │    │     有变化 → verified=true                      │  │
│  │    │     无变化 → 重试（最多 3 次）                   │  │
│  │    │                                                 │  │
│  │    ├─ 连续失败处理：                                 │  │
│  │    │     ≥3 次失败 → 请求用户介入（悬浮窗）           │  │
│  │    │     用户说"已手动处理" → 继续观察               │  │
│  │    │                                                 │  │
│  │    └─ 返回 VerifyResult{success, reason, before, after}│
│  │                                                     │  │
│  └─────────────────────────────────────────────────────┘  │
│                          │                               │
│                          ▼                               │
│  ┌─ Step 6: 记录与反馈 ────────────────────────────────┐  │
│  │                                                     │  │
│  │  记录到 _executionHistory                           │  │
│  │  追加对话历史（保持 MAX_DIALOG_TURNS=6 轮）          │  │
│  │  更新进度摘要（progressNotes，保持 MAX_PROGRESS_NOTES=3）│
│  │  悬浮窗更新进度                                     │  │
│  │  检查长时间无进展（5 分钟）→ 推送通知提醒            │  │
│  │                                                     │  │
│  └─────────────────────────────────────────────────────┘  │
│                          │                               │
│        ┌─────────────────┼─────────────────┐             │
│        ▼                 ▼                 ▼             │
│    ✅ 完成        ❌ 连续失败       🔄 继续下一步          │
│    task_done    ≥3次且用户介入    回到 Step 1           │
│    → DONE       → ERROR           → 直到 maxSteps       │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

## 六、授权模式说明

| 模式 | 条件 | 能力范围 |
|------|------|---------|
| **SHIZUKU** | Shizuku 服务已授权 | 全部能力：shell 命令 + 无障碍操作 |
| **ACCESSIBILITY** | 无障碍服务已开启 | 点击/滑动/输入/按键/启动应用 |
| **READONLY** | 两者都不可用 | 仅观察和分析，拒绝自动执行 |

模式切换由 [CapabilityManager](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/execution/CapabilityManager.kt) 实时监控，转译层据此选择执行通道。

### 6.1 运行期通道切换（失败即换路）

授权模式只决定**首选**通道。执行失败后 [ExecutionCore](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/engine/execution/ExecutionCore.kt) 会自动换通道再试，并且不再把"接口返回成功"当成真的生效：

| 场景 | 首试 | 自动切换顺序 |
|------|------|--------------|
| 启动应用（open_app） | 无障碍 Provider | shell `monkey -p pkg 1` → 主应用自身 `startActivity` |
| 打开深链（open） | 无障碍 openUri | shell `am start -a VIEW -d` → 主应用自身 `startActivity` |
| 点击/长按/滑动/滚动/输入/按键 | 无障碍手势 | shell `input tap/swipe/text/keyevent` |
| shell 命令 | Shizuku / ADB / Termux | 通道失效时翻译为等价无障碍动作 |

- 只有"动作根本没交付"（[VerifyResult.notDelivered](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/engine/execution/VerifiedClickExecutor.kt)）才换通道；"已交付但页面未确认"不重复执行，避免发送/提交/删除类按钮的重复副作用。
- 启动应用按 [launchAppRobust](file:///d:/xkx/xkx_appproj/happy_phone%20agent/app/src/main/java/com/phoneagent/engine/execution/ExecutionCore.kt#L925-L978) 逐级验证"目标应用真的到了前台"才判成功；三级都确认不到就如实报失败，避免部分 ROM 静默拦截后台 startActivity 时，AI 反复用同一条无效通道启动。

## 九、关键设计原则

1. **意图与执行分离**：AI 只输出意图，端侧负责转译和执行通道选择
2. **端侧决策优先**：弹窗/广告/加载/异常/完成页本地处理，节省 API 调用
3. **带验证执行**：每次动作执行后通过页面指纹对比验证是否生效
4. **三态授权**：根据设备权限动态选择执行通道，降级 gracefully
5. **异常记忆复用**：命中历史异常指纹时直接复用解决方案，跳过 AI 调用
6. **上下文长度控制**：保留最近 6 轮对话 + 3 步进度摘要，避免上下文膨胀
7. **安全保护**：支付/银行页面强制 READONLY，敏感数据脱敏
8. **用户协作**：悬浮窗支持澄清/批准/指导/接管，人机协同完成任务

## 十、构建期防线

这些闸门把"文档里写着的约定"变成"构建时一定会检查的规则"，避免约定随代码漂移：

| 闸门 | 触发时机 | 作用 |
|------|------|------|
| `:app:verifyProviderAssets` | `mergeDebugAssets` / `mergeReleaseAssets` 之前 | 比对镜像内 Provider APK 与 `provider` / `provider-api` 源码指纹（`config/provider-assets/*.sha256`），不一致直接失败并提示执行 `:app:syncProviderAssets`，防止旧 Provider 被打进包 |
| `:app:checkDetektBaseline` | `check` | detekt 基线条目只减不增：追加豁免条目即失败；条目变少时自动回写更小的下限（`config/detekt/baseline-count.txt`） |
| `runCatchingLogged` | 运行时 | 执行链路里被降级吞掉的失败统一记一条带堆栈的 WARN（logcat 与应用内调试页同源），不再"功能静默失效、日志一片空白" |
| 截图复用 | 运行时 | 页面指纹与上一轮一致时复用上一帧 Bitmap（同时命中 AiClient 的 base64 缓存），指纹变化立即重拍，不会把过期画面喂给视觉模型 |
| `VerifyRules.stepSettleMs` | 运行时 | 步后等待按动作类型取值：只说不改页面的动作（SAY / REMEMBER / DEVICE_QUERY）等 60ms，其余保持 400ms |
| 任务级设置快照 | 运行时 | `ExecutionCore` 通过 `settingsSnapshot` 复用主循环已读的设置，不再每条 shell 命令都挂起读一次 DataStore |
| `IntentTypeCoverageTest` | 单测 | 意图表闭合性：反射比对「源码常量 = `ALL`」、`TO_ACTION` 键合法、`ALL` = 转译表 ∪ `VIA_OTHER_CHANNELS`。新增意图忘了接转译层会直接红，而不是等 AI 输出该意图时才得到一句"未知意图" |
| `VoiceAssistantDetector`（provider-api） | 编译期 | 语音助手探测（系统入口优先 / 厂商兜底 / 唤醒候选上限）与「优先系统应用」的选包规则只在 provider-api 存一份，主应用与 Provider 共用，避免两端候选名单各自漂移 |

## 十一、任务收尾与共享事实层的边界

两个"从大文件里搬出来"的结构性调整，都是为了把**没有主循环语义的代码**从 `AgentEngine` 剥离：

| 组件 | 位置 | 说明 |
|------|------|------|
| `TaskFinalizer` | `engine/runtime/TaskFinalizer.kt` | 任务记忆终态、模板健康回写、记忆提炼。三者都发生在任务结束那一刻，与决策逻辑无关，但原先是 `AgentEngine` 里 3400 行的一部分。收尾所需状态全部在 `EngineStore` 上，因此不需要回调钩子——引擎只保留「何时收尾」的判断（先落终态、再做耗时提炼的顺序不变） |
| `VoiceAssistantDetector` / `pickPreferredPackage` | `provider-api/.../a11y/` | 跨进程两端都需要**同一份事实**：助手探测结果与"优先系统应用"的选包规则。放在 provider-api 后，主应用与 Provider 依赖同一实现，纯函数部分（`orderedTargets` / `pickHandler` / `vendorFallback`）可直接 JVM 单测 |

> `Audit 结论` 里提到的「主应用与 Provider 各有一套 ActionExecutor」经核实已不成立：
> 主应用侧 `device/a11y/ActionExecutor.kt` 现在只是 AIDL 客户端门面（把 `NodeSelector` 交给 Provider，
> 由 Provider 在当前活节点树上重新定位），真正的执行实现只有 `ProviderActionExecutor` 一份。
> 同理 `AgentAccessibilityService` 也只保留状态观察与读屏/截图入口，不再继承 `AccessibilityService`。
