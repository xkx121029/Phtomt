## 一、v2.2 核心变化总览

| 维度 | v2.0 | v2.2 |
|------|------|------|
| AI 输出 | 可执行命令（含寻址、坐标、通道） | **意图（做什么、对什么做）** |
| 命令生成 | AI 负责 | **端侧转译层负责**（按授权模式） |
| 任务执行 | 每步都问云端 | **按规模分层：脚本执行 / 分层规划** |
| 重复任务 | 每次走完整规划 | **模板库命中零调用** |
| 执行方式 | 写死 | **用户可热切换（脚本 / 边执行边思考 / 智能）** |
| 长线任务 | 不支持 | **阶段切分 + 检查点续传** |

## 二、意图-转译架构（v2.2 的基础）

### 2.1 核心思想

**AI 说"做什么"，端侧决定"怎么做"。**

```
改造前：AI 决策 → 判断通道 → 生成命令 → 端侧执行
              （AI 负担重、容易错、和授权模式耦合）

改造后：AI 决策 → 输出意图 → 端侧转译 → 执行
              （AI 只管决策，端侧按授权模式转译）
```

### 2.2 九种意图

| 意图 | 含义 | 必带字段 |
|------|------|----------|
| `open_app` | 打开应用 | app（应用名） |
| `tap` | 点击 | target |
| `input` | 输入文字 | target + text |
| `swipe` | 滑动 | direction |
| `press` | 按键 | key（back/home/enter） |
| `wait` | 等待 | wait_ms |
| `scroll_to` | 滚动查找 | target |
| `finish` | 任务完成 | summary |
| `give_up` | 放弃 | reason |

### 2.3 目标定位（target）三级策略

```json
{"by": "id", "value": "node_search"}     // 精确 id
{"by": "text", "value": "搜索"}           // 控件文字
{"by": "hint", "value": "右上角的搜索图标"} // 语义描述（视觉定位）
```

**AI 永不输出坐标。** 坐标由端侧定位目标后自动计算。

### 2.4 转译矩阵（端侧按授权模式生成命令）

| 意图 | Shizuku 模式 | 无障碍模式 | 只读模式 |
|------|-------------|-----------|----------|
| open_app | `monkey -p <包名> ...` | `startActivity` | 提示用户 |
| tap | `input tap x y` | `performAction(CLICK)` | 提示用户 |
| input | `cmd clipboard set + input keyevent` | `ACTION_SET_TEXT` | 提示用户 |
| swipe | `input swipe` | `dispatchGesture` | 提示用户 |
| press | `input keyevent` | `performGlobalAction` | 提示用户 |

AI 对授权模式完全无感知。切换授权模式（开/关 Shizuku）对 AI 透明。

## 三、任务规模三分法

| 规模 | 步数 | 例子 | 执行流程 |
|------|------|------|----------|
| 短任务 | 1~2 步 | "打开微信" | 单次意图直接转译执行 |
| 中等任务 | 3~8 步 | "帮我点早餐" | 脚本执行（一次规划，自主推进） |
| 长线任务 | 9 步以上 | "整理发票上传飞书" | 分层规划 + 检查点续传 |

## 四、中等任务——脚本执行

### 4.1 核心转变

中等任务占日常指令 70% 以上，是优化的主战场。

```
改造前（逐步决策）：每步问云端，5 步任务 = 6~8 次调用
改造后（脚本执行）：规划一次产出脚本，端侧自主推进，5 步 = 1~3 次调用
```

### 4.2 脚本数据结构

脚本每步含三要素：**预期页面**（执行前确认没跑偏）、**意图**（做什么）、**验证点**（执行后确认做成了）。

```kotlin
data class TaskScript(
    val taskId: String,
    val goal: String,
    val steps: List<ScriptStep>,      // 3~8 步
    val confidence: Double
)

data class ScriptStep(
    val index: Int,
    val description: String,
    val expectedPage: ExpectedPage,    // 执行前页面特征
    val intent: AgentIntent,           // 意图
    val verification: VerificationPoint // 执行后验证
)

data class ExpectedPage(
    val appPackage: String?,
    val pageType: String?,
    val keyText: String?
)

data class VerificationPoint(
    val checkType: String,   // page_changed / text_appeared / page_type_matched
    val expectedText: String?,
    val expectedPageType: String?,
    val allowNoChange: Boolean = false
)
```

### 4.3 脚本执行循环

```
每步执行：
  1. 读屏
  2. 端侧决策引擎处理意外（弹窗/加载/异常）
  3. 匹配预期页面 → 不符则偏差处理
  4. 执行意图（转译层）
  5. 验证（指纹对比/文字检查/页面类型）
  6. 验证失败 → 重试 1 次 → 仍失败则偏差回调
```

### 4.4 偏差回调

页面真正跑偏时才问云端。**每次脚本最多 2 次偏差回调**，超过则降级为逐步决策。

| 偏差类型 | 触发 | 处理 |
|----------|------|------|
| 页面不符预期 | 预期页面匹配失败（端侧处理意外后仍不符） | 回调云端修正 |
| 验证失败 | 重试后验证点仍不满足 | 回调云端修正 |
| 目标定位失败 | 转译时找不到目标 | 回调云端换描述 |

### 4.5 效果目标

| 指标 | v2.0 逐步决策 | v2.2 脚本执行 |
|------|--------------|--------------|
| 5 步任务云端调用 | 6~8 次 | 1~3 次 |
| 模板命中时 | — | 0 次 |
| 单步延迟 | 800~1500ms | 300~500ms |

## 五、长线任务——分层规划

### 5.1 三层递进

```
目标（Goal）→ 拆分为 3~8 个阶段
阶段（Stage）→ 每阶段单独规划 5~10 步
步骤（Step）→ 阶段内部执行（复用脚本执行器）
```

**AI 任何时刻只需理解"当前阶段 + 工作记忆"，不必记住整个 50 步任务。**

### 5.2 上下文窗口管理

发给 AI 的上下文固定包含三部分：

```
├── 固定部分：用户目标 + 工作记忆摘要 + 当前阶段
├── 滑动窗口：最近 3 步的动作与验证结果
└── 当前页面数据
```

阶段完成后用一次轻量云端调用压缩成摘要写入工作记忆：

```kotlin
data class StageSummary(
    val outcome: String,    // "成功下载 8 个 PDF"
    val keyData: String,    // "文件名：inv_001.pdf ~ inv_008.pdf"
    val notes: String       // "第 3 个附件网络中断已重试"
)
```

### 5.3 检查点与断点续传

| 保存时机 | 频率 |
|----------|------|
| 阶段完成 | 每次 |
| 阶段执行中 | 每 2 分钟 / 每 3 步 |
| 中断信号（来电/锁屏/断网） | 立即 |
| 进程 onDestroy | 立即 |

恢复时对比"检查点记录的页面"vs"实际页面"，一致则续传，不一致则用接管恢复引擎重新定位。

### 5.4 幂等设计

有副作用的意图（发送/提交/下载/删除）执行前先检查"是否已完成"：

```kotlin
if (intent.isFinalSubmit) {
    val page = screenReader.captureCurrentPage()
    if (page.contains("发送成功") || page.contains("提交成功")) {
        return ExecutionResult(true, "检测到已完成，跳过重复执行", 0)
    }
}
```

### 5.5 看门狗

| 层级 | 超时阈值 | 处理 |
|------|----------|------|
| 单步 | 30 秒 | 失败重试或重规划 |
| 单阶段 | 5 分钟 | 保存检查点，异常协作 |
| 云端调用 | 5 秒 × 2 次 | 网络异常，等待恢复 |

## 六、任务模板库

### 6.1 核心特性

**用户只需编写任务目标，不需要编写任何过程。** AI 生成脚本，模板库负责持久化和复用。

### 6.2 模板数据结构

```kotlin
@Entity(tableName = "task_templates")
data class TaskTemplate(
    @PrimaryKey val id: String,
    val name: String,              // 模板名称
    val goal: String,              // ★ 用户唯一需要编写的
    val scriptJson: String,        // AI 生成的脚本（用户无感知）
    val enabled: Boolean = true,   // 用户可在设置启用/禁用
    val source: String,            // preset / manual / auto
    val executionCount: Int = 0,
    val successCount: Int = 0,
    val failedStreak: Int = 0      // >=3 标记失效
)
```

### 6.3 三种模板来源

| 来源 | 说明 | 匹配优先级 |
|------|------|-----------|
| preset（系统预设） | 内置高频任务 | 低 |
| auto（自动学习） | 执行成功的任务自动入库 | 中 |
| manual（用户手动） | 用户只写目标创建 | 高 |

### 6.4 用户创建流程（只写目标）

```
设置 → 任务模板 → 新建
  → 输入"帮我点早餐"（只写这个）
  → [生成执行脚本] → AI 生成 3~8 步脚本
  → 展示步骤预览 → 用户确认保存或重新生成
```

### 6.5 模板匹配与健康管理

```
用户下达任务
  → 模板匹配（Jaccard 相似度 > 85%）
    ├── 命中 + enabled + failedStreak<3 → 复用脚本（零云端调用）
    ├── 命中 + failedStreak>=3 → 标记失效，走云端生成新脚本
    └── 未命中 → 云端生成脚本 → 成功自动入库
```

每次执行后更新健康状态：成功 → failedStreak 清零；失败 → failedStreak+1。

### 6.6 模板进化

脚本执行成功后，用真实定位结果微调模板脚本（by_hint 逐渐替换为精确 id/text），让模板越用越准。

## 七、执行策略热切换

### 7.1 三种策略

| 策略 ID | 显示名 | 说明 |
|---------|--------|------|
| `auto` | 智能选择（推荐） | 根据任务特征自动选 script 或 react |
| `script` | 规划后按脚本执行 | 一次规划，自主推进，快而省 |
| `react` | 边执行边思考 | 每步问云端，灵活但慢 |

### 7.2 智能选择规则

```kotlin
when {
    task.matchedTemplate != null -> script      // 模板命中必走脚本
    task.isScriptable -> script                 // 步数/内容/App 适合脚本化
    else -> react                               // 动态内容多，逐步骤决策
}
```

`isScriptable` 判断：步数 3~8、无动态内容、无不可逆操作、App 熟悉度高。

### 7.3 热加载机制

用户切换策略后**立即生效**，无需重启，正在执行的任务也能平滑交接：

| 切换场景 | 生效时机 |
|----------|----------|
| 任务未开始 | 立即 |
| 中等任务执行中 | 下一步（剩余步骤交接给新策略） |
| 长线任务执行中 | 下一阶段 |
| react 执行中 | 立即（每步本来就要问云端） |

**不允许切换的时刻**：不可逆操作执行中、目标定位进行中、检查点保存中——当前原子操作完成后才切换。

### 7.4 策略与模板的交互

用户显式选择的策略优先于模板优化：

| 用户选择 | 模板状态 | 实际执行 |
|----------|----------|----------|
| auto | 命中 | script |
| script | 命中 | script |
| react | 命中 | **忽略模板脚本，走 react**（尊重用户） |
| auto | 未命中 | 按 isScriptable 判断 |

## 八、统一架构总图

```
用户下达任务
    │
    ▼
【规模判断】1~2 / 3~8 / 9+ 步
    │
    ├── 短任务 → 单次意图 → 转译 → 执行
    │
    ├── 中等任务（3~8 步）
    │   ├── 查模板库 → 命中 → 复用脚本（零调用）
    │   ├── 未命中 → 云端生成脚本
    │   └── ScriptExecutor 执行 → 偏差 ≤2 次回调云端
    │
    └── 长线任务（9+ 步）
        ├── 阶段切分（云端：目标 → 3~8 阶段）
        ├── 每阶段内部复用 ScriptExecutor
        ├── 阶段完成 → 摘要压缩 → 工作记忆
        ├── 检查点持久化 → 中断续传
        └── 看门狗 + 幂等保护
            │
            ▼
      【执行策略层】（用户可热切换）
      ├── script：脚本执行
      ├── react：逐步骤决策
      └── auto：智能选择
            │
            ▼
      【意图转译层】
      ├── IntentTranslator（意图 → 命令）
      ├── IntentResolver（id → text → 视觉定位）
      └── AppNameResolver（应用名 → 包名）
            │
            ▼
      【执行层】
      ├── Shizuku / 无障碍执行器
      ├── LocalDecisionEngine（端侧处理弹窗/加载/异常）
      └── RobustStepVerifier（执行验证）
```
