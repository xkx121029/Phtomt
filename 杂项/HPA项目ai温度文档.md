## 一、什么是 Temperature

`temperature` 是控制模型输出随机性的参数。范围 0~2。

- 温度越高 → 模型越"敢想"，输出更多样但可能跑偏
- 温度越低 → 模型越"老实"，输出更稳定但可能重复同样的错误

```
0.0  完全确定，每次都选概率最高的词
0.3  很谨慎，偶尔换说法但大体不变
0.7  有创造力，输出有变化但不出格
1.0  默认值，创造性确定性各半
1.5  放飞自我，可能出彩也可能翻车
```

## 二、Phantom 各场景的 Temperature 配置

不同 Prompt 对确定性和创造性的要求截然不同：

| # | Prompt | Temperature | 理由 |
|---|--------|-------------|------|
| 二 | 歧义检测 + 规划合并 | **0.3** | 既要理解模糊意图，又不能过度敏感（明明指令很明确还非要问用户） |
| 三 | 每步决策 | **0.1** | 动作指令必须精确——id 不能编、坐标不能歪、action 不能写错 |
| 四 | 执行验证 | **0.1** | 判断是二元的：页面变了还是没变，不需要"创造性"判断 |
| 五 | 异常重规划 | **0.5** | 原来的策略失败了，鼓励真正换个思路，而不是换一种说法重试 |
| 六 | 用户指导决策 | **0.15** | 用户给了明确提示，严格按提示执行，不要自作主张 |
| 七 | 接管恢复 | **0.3** | 需要灵活匹配页面和计划，但判断不能太飘 |
| 八 | 批量规划 | **0.3** | 需要识别多任务连接词并拆分，但不应过度拆分 |

## 三、端侧动态调整逻辑

同一次任务中，temperature 根据上下文动态变化：

```
正常决策路径：全部 0.1
用户介入路径：用户给了提示 → 0.15
异常重试路径：失败 3 次进入重规划 → 0.5
```

```kotlin
private fun resolveTemperature(
    promptType: PromptType,
    context: TaskContext
): Double {
    return when (promptType) {
        PromptType.DECISION -> {
            when {
                context.consecutiveFailures >= 3 && context.isReplanAttempt -> 0.5
                context.hasUserHint -> 0.15
                else -> 0.1
            }
        }
        PromptType.PLANNING, PromptType.RECOVERY, PromptType.BATCH_PLANNING -> 0.3
        PromptType.VERIFICATION -> 0.1
        PromptType.USER_GUIDANCE -> 0.15
    }
}
```

## 四、调试指南

| 现象 | 调整方向 |
|------|----------|
| 动作千篇一律，页面不同也输出类似动作 | 提到 0.1（当前可能低于 0.05） |
| 同一页面前后两次输出不同动作 | 降到 0.05 |
| confidence 值飘忽不定 | 降到 0.1 |
| 重规划后和原计划几乎一样，只换了措辞 | 提到 0.5 |
| 歧义检测过度敏感（明确指令也弹选项） | 降到 0.2 |
| 歧义检测太迟钝（模糊指令直接规划了） | 提到 0.35 |
